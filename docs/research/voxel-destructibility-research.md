# Local World Destruction — Final Feasibility Report (Godot 4.6.3, Hype Raiders)

## 1. Verdict

**Yes — a visually-identical world that crumbles locally where the player shoots is achievable in Godot 4.6.3 stable, without lowering visual quality, but ONLY via one specific approach: extending the project's already-shipped `BreakableGlass` index-keyed destruction pattern to building parts as a server-authoritative "breakable chunk" system.** The hard "must look identical" constraint is satisfied precisely because this approach never re-meshes, re-textures, or geometrically subtracts anything at runtime — it keeps the authored triplanar-PBR `MeshInstance3D` boxes intact and adds destruction as a *runtime state-swap + decal/debris FX layer* on parts that are *already discrete `StaticBody3D` segments*. Every other researched family — runtime CSG/mesh-boolean carving, voxelization (Zylann `godot_voxel`, blocky or smooth/Transvoxel), and alpha-clip/SDF hole-punching — fails the look gate (rounds corners, drops to a 4-texture triplanar splat shader, exposes flat untextured void faces, or forces `ShaderMaterial` onto every wall and breaks the `StandardMaterial3D`-only invariant) and/or carries unacceptable runtime perf and co-op-determinism cost. The decisive enabling facts are that the buildings are **not** monolithic meshes — `ProceduralBuildings._solid()` already splits every wall/floor/roof/pillar (and even a window-holed wall) into independent `StaticBody3D` boxes — and that a working, co-op-safe, golden-snapshot-clean local-breakage system (glass panes) already exists in-repo to clone verbatim. The honest caveat: "destructible" here means *believable localized cosmetic breakage + cover/penetration change*, **not** Rainbow Six-style pinpoint procedural holes or real structural collapse — those require either a bespoke stencil-hole shader subsystem (medium-high risk to material parity) or load-propagation physics Godot 4.6.3 simply does not have.

## 3. Recommended Approach — `BreakableChunk` (detailed)

### 3.1 Why it uniquely passes the HARD "must look identical" gate

The constraint is not "looks similar" — it is **byte-for-byte the current authored look until something is shot, and no blockier/lower-quality anywhere**. Only #1 guarantees this *by construction*:

- It **never re-meshes or re-textures** a building. The pristine state is the exact same `BoxMesh` + `material_override` triplanar-weathered PBR (`ProcMaterials.streaked/weathered/corrugated`) the world ships today. Until a part is hit, the renderer draws precisely what it draws now — the idle cost and pixels are identical (the buildings.dev session benchmarks in CLAUDE.md — field 180 fps / beacon 240 / temple 169 — are untouched).
- Destruction is a **runtime state-swap on an already-discrete part**, not a geometric operation that can round, soften, or void-out a surface. The "crumble" is authored: a pre-built damaged-box variant (cracked-edge mesh reusing the same material), a `rubble_pile()`-style fallen-chunk cluster (`procedural_buildings.gd:541-562`), `Decal3D` scorch/cracks at the bullet's `hit_point`, and a pooled debris `GPUParticles3D` burst oriented along `_last_hit_normal`. None of these introduce a flat untextured face or a blocky silhouette — they are content you control, made of the same materials.
- Because the part is **already its own `StaticBody3D`**, "crumble exactly where the player shoots" is *native granularity*, not something we synthesize by cutting. The weapon raycast already returns the exact collider; breaking it is local by definition.

This is the only family where look-preservation is "yes," not "partial" — every carving/voxel/alpha-clip technique is "partial" or "no" specifically because it alters the surface itself.

### 3.2 How it hooks into the existing precedent (concrete wiring)

The `BreakableGlass` system is a working, co-op-safe, determinism-safe local-destruction system already in the repo. We clone its discipline:

**Build side (`procedural_buildings.gd`):** Mark chunk-able `_solid()` parts (wall segments, cover, low rubble-prone parts) as `BreakableChunk extends StaticBody3D`, assigning a deterministic build index from a new `_chunk_seq` counter — the exact discipline as `_glass_seq`, reset to 0 in `arena.gd:259` *before each build* so every peer builds byte-identical. Register each in a `static _registry: Dictionary` resolved by `by_index()` (mirroring `breakable_glass.gd:32,37,45`). **No RNG, no `Time` — `ProcHash`-style counters only**, which is what keeps the build deterministic across all 8 peers.

**Impact side (`weapon.gd`):** The shot already captures everything needed at `:215-217` — `hit_point = result["position"]`, `hit_node = result["collider"]`, `_last_hit_normal = result["normal"]` — and already branches on collider type (`elif hit_node is BreakableGlass: ... request_break_glass(...)` at `:264-267`). The entire weapon-side change is **one parallel branch**:
```
elif hit_node is BreakableChunk:
    NetworkManager.request_break_chunk(hit_node.index, hit_point, _last_hit_normal)
```
`hit_point` seeds the precise crumble origin / decal placement; `_last_hit_normal` orients the debris outward. World impacts already spawn dust FX via the `FXPool` (`weapon.gd:305+,:314`) — debris bursts reuse that pool to avoid node/material churn.

**Replication side (`NetworkManager.gd`):** Add a `request_break_chunk` / `_server_break_chunk` / `_chunk_broken_rpc` trio mirroring the glass trio at `:383-409`: a client `rpc_id(1)`s the server, the server validates (`chunk.broken` guard), emits noise (a wall is louder than glass — tune the radius), then `_chunk_broken_rpc.rpc(index, hit_point, normal)` with `@rpc("authority","call_local","reliable")` so **every peer** runs `chunk.break_local()`. Grenades break in a radius via a static `break_chunks_in_radius()` analogous to `breakable_glass.break_in_radius()` (`:52-56`), called from `grenade.gd`.

**Break itself (`break_local()`):** idempotent (guard like `shatter()` at `breakable_glass.gd:61-82`): swap the pristine box mesh for the pre-authored damaged variant, spawn the pooled debris FX + decals at `hit_point`, emit a new `Events.chunk_broken`. **Collision and navmesh deliberately stay unchanged at runtime** (see 3.4).

### 3.3 Co-op replication

Solved by the glass pattern — **no new netcode model**. Break state is a single int (the index) per break, server-authoritative, replicated by index because wall roots are anonymous Node3Ds whose paths differ per peer (`breakable_glass.gd:8-14`). Per-build only, never persisted to disk (`:14`); a restart/new-raid rebuilds everything pristine — matching the existing world-reset model (glass, power caches). Debris/decal physics stay **purely local/visual** (never server-authoritative), so they cannot desync; only the "this indexed chunk is broken" bit crosses the wire. The one known gap (shared with glass) is **late-joiners** missing already-broken state — but walls are more load-bearing for cover/LOS than glass, so the recommendation is to have the server replay the broken-index set to a joining peer (a small catch-up array), which glass currently skips.

### 3.4 Golden determinism

This is the strictest gate and it is **satisfiable with one intended re-capture**. `GoldenSnapshot.capture` folds every child under `NavigationRegion3D` (name/class/quantized transform + MultiMesh buffers) at **build time** (`golden_snapshot.gd:38-81`); `tools/lint/check_golden.py` byte-compares against `golden_world.json`.

- Adding `BreakableChunk` index plumbing at build changes node count/names/classes under `Geometry`, so the checksum WILL shift — this is an **intended world change → legitimately re-capture with `--capture`** per CLAUDE.md (not silencing a diff).
- **Runtime breaks never retroactively alter the captured baseline** — the snapshot checksums the *initial constructed tree*, exactly why glass is golden-clean despite panes being StaticBodies under `Geometry` and `shatter()` mutating them at runtime.
- **Lowest-churn variant:** attach the index + registry entry to the existing `_solid` StaticBody *without adding new persistent child nodes at build*, and spawn damaged geometry/FX only on break (runtime, transient, pooled, `@`-named — `_fold_node` already collapses `@`-prefixed auto-named nodes to `@anon` at `:64-65`, and Grass_* tiles are skipped, so pooled runtime FX won't pollute the baseline). This keeps the re-capture diff minimal and stable.

### 3.5 Navmesh

`Arena.tscn:14` bakes the navmesh from layer-1 static colliders (`geometry_parsed_geometry_type=1`, `geometry_collision_mask=1`), once at build, threaded, with a fragile self-healing commit verifier (`arena.gd:426-478`). A mid-raid 320×320 re-bake is expensive and race-prone. Therefore the design rule is firm: **a chunk break must NOT alter collision at runtime** — keep it cosmetic + bullet-penetration/cover at most. Enemies keep their original baked routes (the glass precedent — a broken pane doesn't open an AI path). If a specific breach *must* open a passage, pre-bake the navmesh as if that gap exists (design-time), never re-bake live. Keeping collision intact entirely sidesteps the hazard. Debris RigidBodies, if used, must stay OFF the nav-bake layer or they corrupt pathing.

### 3.6 Scope honesty

This is **decorative + cover/penetration chunk-knockout**, not structural collapse. Godot 4.6.3 has no load-propagation solver (proposal #7782 unimplemented), so shooting a pillar will not drop a roof. Set that expectation up front — it is the same scope the genre's non-AAA titles ship.

## 4. Rejected Approaches (and why — especially blockiness)

- **Voxelization, blocky mesher (`godot_voxel`):** literally produces the blocky/Lego look the user explicitly forbids. Rejected outright.
- **Voxelization, smooth/Transvoxel (`godot_voxel`):** fails the look gate for two independent, unavoidable reasons. (1) Marching cubes / Transvoxel **interpolate surface vertices → round sharp 90° corners** (the exact feature the boxy buildings depend on); the only meshers that preserve sharp edges (Dual Contouring / Extended MC) are on `godot_voxel`'s *future* roadmap, not in 4.6.3. (2) Smooth voxel terrain **cannot use `StandardMaterial3D`** — it requires a custom triplanar splat shader capped at ~4 textures/16 varieties (Mixel4), no UV mapping, which cannot reproduce the ~109 bespoke per-surface weathered materials, the transparent breakable glass, or emissive lamps. It also forces either a custom engine binary (breaks the portable Windows exe + macOS universal/ad-hoc-signed pipeline) or the self-described "less-tested / may crash" GDExtension edition, plus a wholesale rewrite of `ProceduralTerrain`/navmesh/golden-snapshot and new per-shot edit replication (`godot_voxel` ships no co-op edit-sync). Architecturally it is a *terrain* system and cannot make hand-authored `MeshInstance3D` buildings destructible at all without voxelizing them — which is the look regression itself.
- **Runtime CSG / mesh-boolean carving:** Godot 4.6 docs state `CSGShape3D` is **prototyping-only, "significant CPU performance cost,"** boolean output yields very-slow concave collision; a community repro **lags at 15–20 holes in a single wall**, and there is no production-grade runtime mesh-boolean GDExtension for 4.6.3 (Manifold was absorbed into editor CSG in 4.4, not exposed as a fast runtime carve API). Also breaks determinism (float-fragile boolean output across peers) and the clean-BoxShape navmesh contract. Rejected on perf + determinism.
- **Alpha-clip / SDF hole-punch shader:** gives a *real* see-through hole but is the weak link: it **forces `ShaderMaterial` onto every wall part**, violating the project's documented `StandardMaterial3D`-only invariant (enemy hit-flash override, triplanar weathering, shared cached-material batching all depend on it); per-instance uniforms are capped at 16 with no arrays/textures, so multi-hit accumulation needs a per-part SubViewport damage-paint subsystem (heavy new deterministic-replication surface); and a hole in a single-box wall reads as a **flat black void with no thickness** — *lower* perceived quality exactly at the damage, the opposite of the requirement. Rejected as a foundation (possible Phase-2 polish only, see Risks).
- **Stencil-buffer hole (standalone):** is **visual-only** — it discards pixels but geometry, collision, bullet-blocking, LOS, and navmesh all stay intact, so a stencil hole you can still shoot/walk through *misleads players*. Viable only as a hybrid with separate collision edits + custom stencil-aware shader (same material-parity risk as alpha-clip). Not a standalone solution.
- **Authored-`.glb`-swap pre-fracture (off-the-shelf plugins: VoronoiShatter, Jummit, Destructibles-CSharp, the-dunk/Godot-Destruction):** every plugin assumes buildings are authored `.glb` cell-fractured in Blender. This project's buildings are **generated at runtime in GDScript** — there is no mesh file to fracture, and hand-authoring fractured `.glb`s abandons the deterministic seeded procedural buildings and forces a perfect hand-match of the triplanar look (→ drift → the forbidden quality loss). Lift the Voronoi *math* if needed, never the *lifecycle*; none ship localized or networked destruction anyway.

## 5. Risks, Unknowns, and a De-risking Proof-of-Concept

**Risks / unknowns:**
1. **Look-drift at the break itself (the #1 risk).** The pristine state is guaranteed identical; the *damaged* state is authored content. A poorly-authored damaged-box variant or exposed flat interior face would read as lower quality. Mitigation: rely on the project's **triplanar world-space materials** (the same noise continues across a cut for concrete/metal — a genuine advantage here), tint cut faces, and lean on decals + debris to sell depth. Must be art-QA'd per material via the `render` harness command.
2. **Granularity ≠ pinpoint.** Breaking a whole `_solid` segment reads as "this panel blew apart," not an R6 pinpoint bullet hole. Acceptable for "crumble where shot" at part granularity; pinpoint holes need the Phase-2 stencil shader (material-parity risk). Don't subdivide walls into a brick grid to get finer holes — that raises node/draw-call count and is the one place blockiness could creep in.
3. **Debris perf under 8-player simultaneous demolition.** Naive eternal RigidBody debris tanks FPS. Mandatory: hard global concurrent-debris cap (≤150–250), `can_sleep`, freeze→StaticBody on settle, timed despawn/fade, distance-gating (instant-rubble far from any camera), prefer the in-repo `FXPool` for bursts, and Jolt as the physics backend if RigidBody shards are used. Static rubble via `MultiMeshInstance3D` = 1 draw call.
4. **Late-joiner catch-up.** Glass skips it; walls are load-bearing for cover, so add a server-side broken-index replay on join.
5. **Golden re-capture must be the *intended* kind.** Build-time index plumbing legitimately shifts the checksum once (`--capture`); thereafter any *accidental* diff is a real determinism regression. Keep build indices strictly `ProcHash`-counter-based.
6. **Collision/navmesh temptation.** If a designer later wants enemies to path through breaches, that re-opens the fragile 320×320 re-bake hazard. Keep the v1 rule: breaks are cosmetic + cover/penetration, navmesh frozen.

**Suggested minimal PoC (de-risk before committing, ~1–2 days):**
1. Pick **one** building (e.g., a warehouse wall segment from `build_warehouse`). Convert its `_solid` wall parts to `BreakableChunk` with a `_chunk_seq` index + static registry — *no other building touched*.
2. Wire the single `weapon.gd` branch + the `NetworkManager` `request_break_chunk` trio (copy the glass trio, change names).
3. Implement `break_local()` as: hide pristine box → spawn a hand-authored cracked-box variant reusing the same `material_override` + a pooled debris `GPUParticles3D` + a `Decal3D` scorch at `hit_point`. Collision unchanged.
4. **Verify the two hard gates explicitly:** (a) run `tools/lint/check_golden.py` — confirm it diffs ONCE at build, re-capture, then stays byte-identical across reboots; (b) drive a 2-process co-op smoke (`--server` + `--client`) via the harness, break the wall on the host, confirm the client shatters the *same indexed chunk* byte-identically and that a late-join replays it.
5. **Art-QA the damaged look** via the `render` harness command + an in-world screenshot under the cold-cinematic grade — get a 3-critic-panel sign-off that the broken state is not lower-quality than intact. This single screenshot is the real go/no-go for the whole feature.

If the PoC's broken-state screenshot passes the look bar and golden stays stable, the pattern scales to all buildings by tagging more `_solid` parts. If the broken look disappoints, escalate the *break visual* to the Phase-2 stencil-hole hybrid (custom shader) — but only after confirming the cheaper state-swap is the bottleneck, since the shader path carries the material-parity risk.

# Local World Destruction — Feasibility Research (Godot 4.6.3, Hype Raiders)

**Verdict: Feasible without lowering visual quality, by extending the existing index-keyed `BreakableGlass` replication pattern to a new server-authoritative "breakable chunk" system — NOT by runtime mesh-cutting/CSG/voxelization (those are what cause the blockiness the user rejects).** The codebase already ships a working, co-op-safe, golden-snapshot-clean local-breakage system (glass panes). Walls are made of the *same* `_solid()` building block as panes, so the precedent extends cleanly. Details below.

## (1) How buildings are currently built

`scripts/visual/procedural_buildings.gd` (a `RefCounted`, all-static) assembles every structure from **primitive `BoxMesh`/`CylinderMesh` parts in building-local space**, deterministically seeded via `ProcHash.h/hf` (no RNG). Two part kinds:

- **`_solid()`** (`procedural_buildings.gd:244-262`) — the universal load-bearing block for every wall/floor/roof/pillar. Each call creates **one `StaticBody3D` (collision_layer=1, mask=0) with a child `MeshInstance3D` (BoxMesh + `material_override`) AND a child `CollisionShape3D` (BoxShape3D)**. `_solid_cyl()` (`:281-305`) is the cylinder equivalent.
- **`_decor()`** (`:267-274`) — render-only `MeshInstance3D`, no collision (trim, ledges, ribs, canopy beams, vents).

**Granularity is key for this feature:** buildings are NOT merged meshes and NOT single colliders. They are **many independent StaticBody3D parts**. A wall with a window is already split into separate solid segments (left pier, right pier, sill strip, header strip — `wall()` at `:339-455`); a holed floor is up to 4 strip boxes (`_slab_strips` `:474-503`). So "a wall" is already a handful of discrete StaticBody boxes, each individually addressable.

**Composite builders** (`build_tower :596`, `build_warehouse :664`, `build_house :742`, `build_container_yard :871`, `build_temple :941`, `build_snow_lodge`, `build_desert_ruins`, `build_plaza_cover`) call those primitives. The arena instantiates them in `_build_poi_structures` (`arena.gd:259-290`): each building Node3D is added under **`NavigationRegion3D/Geometry/<POI_name>`** (`arena.gd:290`). Materials are authored triplanar weathered PBR via `ProcMaterials.streaked/weathered/corrugated` (`:33-216`) — this is the look that must be preserved.

Batching note for the golden snapshot: render-only cosmetic detail (rooftop/street kits) uses MultiMeshes via `ProceduralBuildingDetail`, but those live under the **Arena root, not under NavigationRegion3D** (`arena.gd:74-79`), so they are outside both the navmesh and (mostly) the golden checksum. The structural collidable boxes are individual nodes under `Geometry`.

## (2) How breakable GLASS works — and whether it extends to walls

The glass system (`scripts/world/breakable_glass.gd`) is the **direct template** and proves the whole approach is co-op-safe and determinism-safe:

- A pane is a `BreakableGlass extends StaticBody3D` (layer 1) built inside `wall()` at `procedural_buildings.gd:418-443`, carrying a deterministic integer `index` from `_glass_seq` (a build-time counter reset to 0 before each build at `arena.gd:259` → identical on every peer).
- **Replication is BY INDEX, not node-path** (`breakable_glass.gd:8-14`): wall roots are anonymous Node3Ds whose paths differ per peer, so node-path RPCs can't target them. Each pane self-registers in a `static _registry: Dictionary` (`:32, :37`). `by_index()` (`:45`) resolves it anywhere.
- **Server-authoritative break path** (`NetworkManager.gd:383-409`): a hit calls `request_break_glass(index)` → host runs `_server_break_glass` directly, a client `rpc_id(1)`s it → server validates (`pane.broken` guard), emits noise 12.0, then `_glass_broken_rpc.rpc(index)` (authority/call_local/reliable) → **every peer** runs `pane.shatter()`.
- `shatter()` (`:61-82`) is idempotent: disables collision (deferred), hides the `Pane` mesh, fires a pooled `GlassShatter` GPUParticles FX (`scripts/fx/glass_shatter.gd`), emits `Events.glass_broken`. Grenades break in a radius via the static `break_in_radius()` (`:52-56`), called from `grenade.gd:116`.

**Does it extend to walls? Yes, structurally — with one caveat.** A wall segment is *already* a `_solid()` StaticBody box, exactly like a pane (which is itself just a StaticBody+Box+Mesh). The pattern that transfers verbatim:
1. Give chunk-able `_solid` parts a deterministic build index from a new `_chunk_seq` (reset in `arena.gd` beside `_glass_seq`).
2. A `BreakableChunk extends StaticBody3D` with a static index registry + `request_break_chunk(index)` mirroring the glass RPCs in NetworkManager.
3. On break: swap the pristine box mesh for a **pre-authored damaged variant + debris FX**, optionally disabling/shrinking collision.

The **caveat** that determines whether quality is preserved: glass simply *vanishes* on break (acceptable for glass). A wall must not vanish or turn blocky. The right move is **state-swap to pre-authored damaged geometry** (e.g., a cracked-edge box, a rubble cluster reusing `rubble_pile()` at `:541-562`, scorch decals, a localized debris GPUParticles burst), NOT runtime geometric subtraction. Localized cosmetic damage (decal + chunk-fall FX + optional small collision pock) keeps the authored triplanar PBR look intact. This is "crumble at the hit point" as a **localized appearance/FX change on an already-discrete part**, which is exactly the granularity the building system already provides.

## (3) What a bullet impact already knows

The shot resolves a stepped ballistic raycast in `weapon.gd:193-227` against `hurtbox_mask` (`collide_with_areas` + `collide_with_bodies`, `intersect_ray`). On a hit it captures **`hit_point` = `result["position"]`, `hit_node` = `result["collider"]`, and `_last_hit_normal` = `result["normal"]`** (`weapon.gd:215-217`). It already type-checks the collider: enemy hurtbox → damage; `elif hit_node is BreakableGlass` → `request_break_glass(...)` (`weapon.gd:264-267`). 

So the impact already has everything a chunk break needs: **exact world hit position, surface normal, and the collider node.** Adding `elif hit_node is BreakableChunk: NetworkManager.request_break_chunk(hit_node.index)` at `weapon.gd:267` is the entire wiring change on the weapon side (one branch, mirroring the glass branch). The normal lets the debris FX orient outward; the hit_point gives a precise crumble origin. World impacts already spawn dust FX (`_on_fired`, `weapon.gd:305+`).

## (4) Hardest integration constraints

**A. Golden determinism snapshot — the strictest gate, but satisfiable.** `tools/lint/check_golden.py` + `GoldenSnapshot.capture` (`scripts/core/golden_snapshot.gd`) folds, for **every child under `NavigationRegion3D`**, each node's name, class, and quantized global transform into a hash (`_fold_node` `:59-81`), plus MultiMesh buffers. **Critical facts that make this survivable:**
   - The snapshot is captured at **build time** (right after the world is built / on demand via the `golden` cmd), and it checksums the **initial constructed tree**. Runtime mutations (a chunk breaking mid-raid) do not retroactively change the captured baseline — the glass system already proves this (panes are StaticBodies under Geometry, yet glass is golden-clean because the *built* tree is identical across peers and `shatter()` is a runtime state change).
   - But **adding chunk nodes / index plumbing at build time WILL change the checksum** because it changes node count/names/classes under Geometry. Per CLAUDE.md, that's an **intended world change → re-capture with `--capture`** (legitimate, not silencing a diff). The hard requirement is **build-time determinism**: indices must come from a `ProcHash`-style counter reset per build (the `_glass_seq` discipline at `arena.gd:259`), never from RNG/`Time`, so all peers build byte-identical and the new baseline is stable.
   - **Safest-quality variant:** keep the break a pure runtime state-swap on **existing** `_solid` parts (attach index + registry to the box without adding new persistent child nodes at build), spawning damaged geometry/FX only on break (runtime, transient, pooled like `GlassShatter`). That minimizes golden churn. Note `_fold_node` already treats `@`-prefixed auto-named nodes as `@anon` (`:64-65`), and Grass_* tiles are skipped — runtime-spawned FX named with `@`/pooled won't pollute the baseline.

**B. Co-op replication — already solved by the glass pattern.** The index-keyed, server-authoritative break (client `rpc_id(1)` → server validate → `authority/call_local` broadcast) is the exact, proven mechanism (`NetworkManager.gd:383-409`). Per-chunk break state is **per-build only, never persisted** (`breakable_glass.gd:14`), and a restart rebuilds everything pristine. No new netcode model is needed — just a parallel `request_break_chunk` trio. The state is tiny (one int per break), so even map-wide cumulative damage is cheap. Late-joiners are the one gap (glass has the same limitation); for walls you'd want the server to replay the broken-index set to a joining peer if persistent visible damage matters.

**C. Navmesh bake.** `Arena.tscn:14` sets `geometry_parsed_geometry_type = 1` (PARSED_GEOMETRY_STATIC_COLLIDERS) + `geometry_collision_mask = 1` — the navmesh is baked **from the layer-1 collision shapes**, and the bake runs once at build (`arena.gd:405-417`, threaded, with a self-healing commit verifier `_verify_navmesh_commit` `:426-478`). **Implication:** if a chunk break **removes or shrinks collision** at runtime, the **navmesh is NOT re-baked** (re-baking the 320×320 mesh mid-raid is expensive and the bake is already race-prone per the verifier comments). This is fine and matches glass: a broken pane disables collision but enemies don't suddenly path through the new gap — the navmesh is frozen from build. So the design constraint is: **breaking a wall chunk should be cosmetic/penetration-affecting at most, not open new AI paths.** If a break must open a passage, either (a) pre-bake the navmesh as if the gap exists, or (b) accept enemies keep their original routes (the glass precedent). Keeping collision intact (damage = visual + bullet-penetration only) entirely sidesteps this.

**D. Physics layers / FX scale.** World geometry is layer 1, mask 0 (`_solid` `:248-249`); bullets ray against `hurtbox_mask` and already register world hits. No layer changes needed. The only perf watch is debris FX volume under sustained fire — the existing **FXPool** (used by `GlassShatter`, `weapon.gd:314`) is the right home; pool chunk-debris bursts the same way to avoid node/material churn.

## Concrete recommendation (research conclusion, not implementation)

Extend the **`BreakableGlass` index-keyed pattern to a `BreakableChunk`** on selected `_solid()` wall/cover parts. Break = **runtime, server-authoritative, replicated-by-index state swap**: pristine box → pre-authored damaged appearance (cracked/scorched material variant + pooled debris GPUParticles + optional `rubble_pile`-style fallen chunk) at the bullet's `hit_point`/`_last_hit_normal`. Keep collision and navmesh **unchanged at runtime** (mirror glass) to avoid AI-path and re-bake hazards. This:
- preserves visual quality (authored PBR meshes/materials, no CSG/voxel/mesh-cut blockiness — those are explicitly the rejected approach),
- reuses the entire proven co-op netcode (`request_break_*` trio in `NetworkManager.gd:383-409`),
