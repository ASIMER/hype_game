# Hype Raiders — Project Guide (read me first)

**Hype Raiders** is an Arc Raiders-style **co-op third-person extraction shooter** vertical slice built in **Godot 4.6.3 stable**. Scavenge a hostile **320×320** urban-ruins map full of AI robots, survive escalating waves (incl. a boss), and reach an extraction zone alive — solo or in up-to-8 co-op. It runs **with zero art assets** (every model falls back to a tinted primitive via `AssetRegistry`).

**Map: 4× expansion (v0.3).** The world is a **320×320 rectangle** X∈[−80,240], Z∈[−80,240] (centre 80,80). The original 160×160 map is the **NW quadrant** (all original content kept its exact coords; bounds in `procedural_terrain.gd` X_MIN/X_MAX/Z_MIN/Z_MAX). The 3 new quadrants each have a **themed landmark + filler POI + a localized climate zone**: **NE→snow** (alpine Lodge + depot), **SW→desert** (sandstone Ruins ×2), **SE→rain** (Japanese Temple + shrine house). New building themes `temple`/`snow_lodge`/`desert_ruins` in `procedural_buildings.gd`; `_POI_DEFS` has 12 POIs (POIMarkers order MUST match the keys — tiers/loot/power-caches map by index). **`ProceduralClimateZones`** (`scripts/visual/procedural_climate_zones.gd`, clones the FogZones discipline) places POINTWISE rain/snow/desert at the 3 landmarks (GPUParticles + ground Decal + FogVolume; render-only, deterministic, `Settings.climate_zones_enabled`/`climate_density`, Graphics-tab toggle+slider). Flora/atmosphere scatter the full rectangle (grass is density-driven + tiled so per-frame cost is unchanged); the river stays in the NW quadrant (shallowed south terminus, banks still split). Enemy spawning got a deterministic golden-angle de-stack jitter (`wave_manager._jittered_spawn`) so a burst on one marker no longer piles vertically. The 4 perimeter wall colliders in `Arena.tscn` (`Walls/Wall*`, layer 1) were resized 162→322 + repositioned to ring the NEW rectangle (were stuck at the old ±80, forming an invisible mid-map cross). **Extraction: 12 zones** (`ExtractionZone`..`ExtractionZone12`) — the original 3 NW + 3 per new biome — all auto-register via the `"extraction"` group (no director change) + get terrain pads in `_collect_pads`. Loot/boosters fill the new quadrants: `arena._scatter_field_loot` drops open-area loot across the L-shaped new region (x>82 or z>82; server-only + replicated), and `_populate_power_caches` gives EVERY new POI (index ≥ 6) a power-cache + scatters 6 more; flora keep-outs (`procedural_flora._POI_RECTS`) + new-quadrant rubble (`_rebuild_scatter`, placed at `height_at`) were added.

- **`docs/AGENT_TEAMS.md`** — the expected `agent_teams` team structure & ownership model for parallel work.

## Release / packaging (portable Windows + macOS builds)
**Timestamped** layout: `export/v<VERSION>/<yyyy-MM-dd_HH-mm-ss>/windows/` + `.../mac/` — every build goes to a NEW dated folder so previous builds are PRESERVED for rollback (older builds are never overwritten; just grab the exe/zip from an earlier timestamp folder). **Build BOTH platforms with one command: `pwsh tools/build/export_all.ps1`** — it generates ONE shared timestamp, runs both export scripts into the same dated folder, and does a post-build exe alive-check. (The individual `export_windows.ps1`/`export_macos.ps1` still work standalone — each takes an optional `-Stamp`; run alone, each generates its own stamp.) Bump the `VERSION` file per release. **Windows:** `pwsh tools/build/export_windows.ps1` → installs the 4.6.3 export templates on first run (one-time ~700 MB), regenerates `scripts/resource_index.gd`, exports a single self-contained exe (pck embedded) + zips it with a README (`windows/HypeRaiders.exe` + `HypeRaiders-v<VERSION>-win64.zip`; friends unzip + run; co-op via Host/Join over UDP 24565). **macOS (built FROM Windows):** `pwsh tools/build/export_macos.ps1` → `mac/HypeRaiders-v<VERSION>-mac.zip` containing a **universal (Apple-Silicon arm64 + Intel) `Hype Raiders.app`** with a built-in **ad-hoc signature** (mandatory on arm64; Godot signs cross-platform, no Xcode), validated structurally (the script asserts the `.app/Contents/MacOS` entry + the fat Mach-O `CAFEBABE` magic) + `README-mac.txt` with the Gatekeeper first-launch steps (right-click→Open / `xattr -cr`) — not notarized (no Apple cert), so the warning is expected; a `.dmg` can't be made from Windows. **Gotchas:** the `macOS` preset (`[preset.1]`) requires the PROJECT setting `rendering/textures/vram_compression/import_etc2_astc=true` (Apple GPUs need ETC2/ASTC — without it the export refuses for arm64/universal; enabling it triggers a one-time texture reimport), and the Godot-made mac zip must ship **AS-IS** — never unzip+re-zip a `.app` on Windows (strips unix exec bits → app won't launch; the README sits NEXT to the zip). `export_presets.cfg` uses **`export_filter="all_resources"`** so the string-loaded `assets/*` + the data `.tres` ship. **Export gotcha (already handled):** `DirAccess` can't enumerate a `res://` dir inside a PCK, so `ItemCatalog`/`Crafting`/`Quests` scan empty in a build — they fall back to **`ResourceIndex`** (generated path lists; loading by explicit path works because Godot remaps it). Drop a new `.tres` → the next build regenerates the index. `export/` is gitignored.

## Architecture at a glance
Systems are **decoupled through autoloads** — they emit/listen on the `Events` bus and read shared data, never referencing each other directly:
- **`Events`** — global signal bus (combat, weapons, loot, extraction, waves, net).
- **`Settings`** — all tunables (player/camera/ADS, enemy `ENEMY_STATS` table, waves, gadgets, `difficulty_mods()`).
- **`AssetRegistry`** — logical id → visual. Resolution order: real `.glb` → **`ProceduralModels.build(id)`** (rich multi-part meshes assembled in code: distinct enemy silhouettes + real item shapes, `scripts/visual/procedural_models.gd`) → CATALOG `parts` → tinted single primitive (game always runnable). `.glb` WINS over a builder — clear an id's `"model"` to use its procedural model. `get_icon` returns an authored PNG (weapons) else falls back to **`IconRenderer`**.
- **`IconRenderer`** — renders any id's 3D model to a transparent texture (off-screen SubViewport) for inventory icons; cache filled by a startup pre-warm so the UI `get_icon` is a sync cache hit (headless → null → UI colored box). Also the model-QA tool: AgentBridge `render` command saves a clean hero shot PNG (see harness). Procedural-model + SubViewport gotchas live in the `procedural-visual-harness` memory.
- **`GameState`** — match phase, wave, peer roster, win/lose resolution, `difficulty` (Easy/Normal/Hard).
- **`MetaProgression`** — persistent between-run profile (`user://profile.cfg`): currency, weapon unlocks, permanent upgrades (incl. **Stash Expansion** → `stash_capacity()`), deploy loadout (weapons) + `bring` (consumable bring-list), **`equipped_attachments`** (`weapon→{slot→att_id}`, at-risk) + **`weapon_perks`** (`weapon→{perk→level}`, permanent, `WEAPON_PERKS`) + daily-contract state (`last_daily_date`/`daily_quest_ids`). `player_mods()` read by player.gd + weapon_controller at match start; `reconcile_attachments()` unequips any attachment no longer in the stash (called on Hub open, after a loss eats it).
- **`ItemCatalog`** — scans `resources/items/*.tres` → `id → ItemData` (shared by loot / stash / loadout / craft).
- **`Stash`** — the **persistent item stash** (`user://stash.cfg`, per-instance via `Settings.user_path`): what you extract is kept here as real items; the at-risk economy (materials/consumables/valuables/**attachments** — weapons stay permanent unlocks). Has a **hard weight cap** (`total_weight()`/`capacity()` = `MetaProgression.stash_capacity()`); a deposit over cap fires `Events.haul_overflow` → the **Manage-Your-Haul** screen (`scenes/ui/HaulManager.tscn`, instanced by `main.gd`: sell/recycle/drop until under cap). Surfaced by the **Lobby/Hub** (`scenes/ui/Hub.tscn`: STASH / LOADOUT / WORKSHOP / SHOP / QUESTS / **GUNSMITH** / RAIDER / **CHARACTER** tabs — GUNSMITH equips at-risk attachments + buys permanent perks).
- **Character customization (procedural modular player)** — the player is now a **procedural robot** built from swappable parts (`scripts/visual/procedural_player.gd`, same helpers as the enemy `ProceduralModels`), NOT the old `raider.glb`. `ProceduralPlayer.build_player(cosmetics)` assembles **head / torso / arms / legs** (≥10 distinct variants each) + a **paint** colour scheme (10) from a FROZEN catalog (`VARIANTS`/`PAINTS`); `AssetRegistry.get_model("player", cosmetics)` routes to it. The **CHARACTER Hub tab** (`scenes/ui/tabs/character_tab.gd`, tab index 7) is the constructor: category selector + a variant grid of `IconRenderer.render_cosmetic(...)` thumbnails (owned/EQUIPPED vs **BUY (CR n)**) + a **live rotating 3D `SubViewport` preview**. Economy in `MetaProgression`: `unlocked_cosmetics`/`equipped_cosmetics` (saved in `profile.cfg`), `is_cosmetic_unlocked`/`unlock_cosmetic`/`set_equipped_cosmetic`/`get_cosmetics()`; free starter variants (cost 0) always available; `Events.cosmetics_changed`. **MP appearance sync**: `player.gd` has a spawn-replicated `cosmetics: Dictionary` (Player.tscn `SceneReplicationConfig`, like `stance`/`downed`) — the authority sets it from its OWN `MetaProgression.get_cosmetics()` at spawn, it replicates to every peer, and a `_physics_process` watcher rebuilds the body (`_build_player_model` → `PlayerAnimator.reinit()`) so **every peer sees each player's chosen look** (verified host↔client). Harness: `raw.py '{"cmd":"cosmetic","action":"equip|buy|grant|get","id":...}'` + `ui hub_character`; `state.players[]` now exposes each player's replicated `cosmetics`.
- **World & match loop** — `scenes/world/Arena.tscn`+`arena.gd` swap the old cube POIs for **procedural modular buildings** (`scripts/visual/procedural_buildings.gd`, themed per POI, spawned at the POI markers *before* the runtime navmesh bake; courtyards left clear around the 3 extraction zones) over a textured ground + atmospheric sky (`resources/default_env.tres`). **Match timer**: `wave_manager.gd` counts `GameState.match_time_left` down from `Settings.MATCH_DURATION`; at 0 it sets `GameState.final_wave` and floods a **final "storm" wave** (interrupts the current wave, raises the alive-cap to `FINAL_WAVE_CONCURRENT`) forcing extraction. The 5 gradual waves are unchanged before it. **`ExtractionDirector`** autoload rotates per-zone **timed windows** (`extraction_zone.is_open()/window_remaining()/set_window()`; only an OPEN zone makes progress; all forced open during the storm). The **'M' Tactical Map** (`scenes/ui/MapUI.tscn`) shows POIs (zones of interest), every evac zone w/ open/closed + countdown, the player, enemies, and the match clock; the minimap mirrors window state; HUD shows the timer + storm banner. **Combat**: shots now have **bullet drop** (`weapon.gd` stepped ballistic raycast under `Settings.BULLET_GRAVITY`/`BULLET_MUZZLE_VELOCITY`, tracer follows the arc), punchier impact FX + enemy stagger, and a crosshair **hit-marker** (`scripts/ui/hit_marker.gd`). The **player model rotates smoothly** with the camera (body yaw is applied at render rate in `player.gd`, not deferred to the 60Hz physics tick).
- **Living threat (AI perception + sound stealth + reactive director)** — enemies are no longer a fixed timed trickle of force-aggro rushers. The FSM (`scripts/enemies/enemy_state_machine.gd`) gains an **`INVESTIGATE`** state (enum appended LAST so the replicated 0/1/2 PATROL/CHASE/ATTACK ints don't shift); `robot_enemy.gd` adds **server-side perception**: it HEARS players (each ~0.4 s retarget tick it reads `player.noise_radius()` — crouch quiet, walk medium, sprint loud, idle faint, downed near-silent; derived from the player's SYNCED position-speed + synced `stance`, NOT velocity) and reacts to loud `Events.noise_emitted` spikes (gunfire/grenade) → walks to the last-heard point (INVESTIGATE), promotes to CHASE on confirmed LOS, gives up after `INVESTIGATE_GIVEUP`. Entering CHASE **cascades** an alert to nearby non-hunter enemies (`alert_to`, refractory-gated). The **`hunter`** flag is still a force-CHASE override, so **wave/storm enemies rush exactly as before** — only NON-hunter **patrols** (spawned between waves) use the new senses and can be **stealthed past by crouch-walking**. Noise is **server-authoritative**: gunfire (`weapon.gd`) + grenades (`grenade.gd`) route through **`NetworkManager.report_noise(pos, radius, kind)`** (host emits directly; a client `rpc_id(1)`s so the SERVER's AI hears it). A **suppressor** (`att_suppressor.tres` `noise_mult=0.35` → `WeaponData.noise_mult`, layered in `weapon_controller._apply_attachments`) shrinks the gunfire aggro radius. New archetypes in `Settings.ENEMY_STATS`: a **caller/"Snitch"** (`robot_caller.gd`/`RobotCaller.tscn`, low HP, keeps distance, its `_strike` fires `Events.enemy_alerted` instead of damage) and an **elite** grunt (`RobotElite.tscn`, tankier + a ×2.5 `WeakPoint` Hurtbox Area). **Weak points** are `Hurtbox` Areas with `damage_multiplier` (head ≈2.0–2.5×, mirroring Bastion's `WeakPoint`) now on grunt/heavy/elite (pure scene; the body Hurtbox is untouched so normal shots still register). The **`AIDirector`** autoload (`autoload/ai_director.gd`, mirrors the `ExtractionDirector` pattern) listens to `enemy_alerted`/loud `noise_emitted` and, on a cooldown, summons reinforcements via the active `WaveManager` (which registers itself); `wave_manager.gd` adds **camp-punish** flank spawns (squad clustered within `DIRECTOR_CAMP_RADIUS` for `DIRECTOR_CAMP_TIME` → hunters spawn around the centroid), **boss-phase adds** (boss < `DIRECTOR_BOSS_ADD_HP` → elite adds once), and between-wave **patrols** (tracked in a separate `_patrols` array, freed at wave start so they never break wave-clear accounting). All gated on `is_local_authority_server()`; reactive spawns cap at `FINAL_WAVE_CONCURRENT`. Harness QA: `raw.py '{"cmd":"spawn","id":"caller|elite|grunt|...","dist":N,"hunter":false}'` (the new `hunter:false` flag spawns a stealthable patrol).
- **Live raid + the long game (world events + risk tiers + 3 progression systems)** — *Dynamic world events*: the **`WorldEventDirector`** autoload (mirrors `ExtractionDirector`, server-only, suspends in the storm) fires mid-raid events on a timer (`WORLD_EVENT_FIRST_DELAY`/`INTERVAL`±`JITTER`): **supply cache** (`scripts/world/supply_cache.gd`+`SupplyCache.tscn`, an Area3D modeled on `extraction_zone` — hold near it → cracks → rarity-weighted loot, guarded), **roaming mini-boss** (`RobotElite`, currency reward on kill), **contested POI** (a POI goes hot for `CONTESTED_POI_DURATION` with extra guards), **environmental surge** (enemy burst / sensor-blackout that disables the minimap). Each emits `Events.world_event_started/ended/progress` + a banner + a node in the **"world_events" group** (with `get_meta("event_kind"/"event_label"/"event_pos")` + `event_ratio()`); the map/minimap/HUD (`map_ui.gd`/`minimap.gd`/`hud.gd`) draw the markers + countdowns. Event enemies spawn via `wave_manager.spawn_reinforcements` (capped at `FINAL_WAVE_CONCURRENT`). Debug-force any event: `raw.py '{"cmd":"event","kind":0-3}'`. *Risk tiers*: the 6 POIs are tiered (`Settings.POI_RISK_TIERS` 1–3; `arena.get_poi_tier()`); **`scripts/loot/loot_tables.gd`** (`LootTables.roll_by_tier`/`roll_for_enemy`, inverse-rarity weighted via `ItemCatalog.ids_of_rarity`) rolls tier-appropriate loot; `arena._populate_world_loot()` finally fills the `$LootCacheMarkers` with world loot at build (server-only → `Net/Loot`; high-tier POIs drop RARE/EPIC), and enemy drops scale with the tier they die in (`loot_spawner.tier_at`). The map shades POIs by `Settings.RISK_TIER_COLORS`. (Gotcha fixed: `LootPickup.spawn_at` now uses `add_child(node, true)` — required under the `Net/Loot` MultiplayerSpawner.) *Three progression systems* (per-peer LOCAL, persisted in `profile.cfg` v0.3.0, fed by the **`Progression`** autoload listening on the Events bus): **Raider Level + XP + skill points** (`MetaProgression.add_xp` from kills/extract/events/rare-loot → levels via `xp_to_advance` → skill points spent in `buy_skill`; the `SKILLS` fold multiplicatively into `player_mods()` incl. a new `loot_mult` consumed by `RaidManager`), **Vendor Reputation** (`grant_rep` on extract/contracts → `rep_tier()` rewards + a shop discount `rep_discount()` applied in `shop_tab.gd`), **Weapon Mastery** (`add_weapon_mastery` per kill, attributed to the killer's active weapon). All shown in a new **RAIDER** Hub tab (`ProgressionTab`) + the **RaidSummary** post-raid breakdown. `state.meta` exposes `xp`/`raider_level`/`skill_points`/`vendor_rep`/`rep_tier`/`weapon_mastery` for the harness.
- **Validation pass (post-Batch-3 correctness + depth)** — audited every added mechanic vs the genre + code, fixed the real bugs: **(co-op) kill XP/weapon-mastery now credits every peer** — `Events.entity_died` fires server-only, so kill credit is routed through the SAME server-auth attribution as the scoreboard (`NetworkManager._on_entity_died` → `_peer_of(killer)` → `Progression.credit_kill()` locally for the host, `_credit_kill_rpc.rpc_id(peer)` for a client) instead of a broken local `is_multiplayer_authority()` check (clients earned nothing before); **AI fully ignores DOWNED players** (`robot_enemy._find_nearest_player`/`_nearest_player_visual` skip `is_downed()` — a down is no longer an instant death, only the bleedout timer threatens it); **revive is server-validated** (`NetworkManager._do_revive` requires the reviver be UP + in range) and **cancels if the reviver takes damage** (`player._update_coop_interaction`); **carry applies `CARRY_SPEED_MULT`** (was defined-but-unused); **world events defer if they can't spawn guards** (`world_event_director._guards_capacity()` via `wave_manager.reinforcement_capacity()` — no undefended caches). Progression got real depth (kept original, NOT an Arc-clone): **Weapon Mastery → a "veteran" ramp** (small recoil/spread/reload reduction per level, layered in `weapon_controller._apply_mastery`), **Raider Level → milestones** (`Settings.RAIDER_MILESTONES`: free weapon/stash/credits at L3/5/8/12, applied idempotently in `MetaProgression._apply_milestones`, folded into `stash_capacity()`/`unlocked`), **weak points get a glowing marker** (`robot_enemy._setup_weakpoint_marker`, render-only). Polish: caller can't frame-1 alert; grenade-alarm threshold is `Settings.ALARM_GRENADE_MIN_LOUDNESS`. (Validated false-positives left alone: Scavenger `loot_mult` is wired in `RaidManager._deposit`; boss-adds read `max_health`.)
- **`RaidManager`** — the per-player raid economy: `deploy()` commits the bring-list **and the loadout weapons' equipped attachments** (pulls them from the local stash, now at risk — `_committed_attachments`); `grant_extraction()` deposits a peer's haul + surviving attachments into ITS OWN stash on extract (host-local or via RPC to a client) + learns blueprints from extracted schematics, then fires `haul_overflow` if over the weight cap. **Death deposits nothing → gear + attachments lost. ## Localization (en base + ru; scalable)
**Scheme: "English-as-key" + Godot auto-translate.** All translations live in ONE file — **`locale/ui.csv`** (`keys,ru[,de,...]`; the key IS the exact English source string; UTF-8; multi-line strings = real newlines inside quotes). Godot imports it to `locale/ui.*.translation`, registered in `project.godot [internationalization]` (fallback=en — English needs NO column: tr() falls back to the key). The language is the **`"language"` setting** (`SettingsManager`, default "en") applied via `TranslationServer.set_locale` — picker in Settings → INTERFACE (its own OptionButton has auto_translate DISABLED so "English/Русский" stay native). **Adding a language = add a CSV column + one `add_item`/lang_codes entry in `settings_menu.gd`.** How it works: Godot Controls AUTO-translate their `text`/`tooltip_text`/`placeholder_text`/OptionButton items at draw time — including text set from code — and re-translate LIVE on locale change; so STATIC strings need only a CSV row, while **format templates/concatenations/`Events.notify` payloads must go through `tr()`** (`tr("WAVE %d") % n` — tr the TEMPLATE; data-names substituted into templates get tr() too). `.tres` display_name/description and the Settings/MetaProgression catalogs are NOT modified — their English values are the CSV keys. **RULES for new code:** any new user-facing string gets a `locale/ui.csv` row immediately; if you EDIT an English string in code/scene/tres you MUST update its CSV key (key drift = silently untranslated); never translate ids/player names/IPs; strings compared in logic stay untranslated.

## UI look ("military glass" — theme-first)
The UI is a **dark translucent "military glass"** skin (Battlefield 2042 / Arc Raiders): chamfered translucent panels, thin light borders, amber accent bars + glow, spaced-caps headings, subtle scanlines, frosted-glass blur behind modals. It is built **in code**, reached three ways:
- **Global theme `assets/ui/theme.tres`** (project.godot `gui/theme/custom`) — every default Control inherits it: **Oswald** body font, **Russo One** heading face (via theme type variations **`HeaderLarge`** 30px / **`HeaderSmall`** 14px dim), translucent chamfered glass Buttons/Panels/LineEdits, amber hover-glow, teal ProgressBar fill (+ an amber **`FillAmber`** ProgressBar variation). Both fonts ship **Cyrillic** for the RU locale (`assets/fonts/`, SIL OFL). Restyling most of the UI = editing this one file.
- **`scripts/ui/ui_style.gd` (`class_name UIStyle`)** — stateless helper, the single source of truth the in-code screens call: palette consts (`UIStyle.AMBER/TEAL/DIM/WHITE/RED/GREEN/GLASS_BG/BORDER_LT`), StyleBox factories (`glass_panel()`, `header_panel(accent)` = glass + accent top bar + glow, `chip(color)`, `glow_fill(color)`), label helpers (`micro_header(text)`, `make_header(label,…)` — both apply the Russo One face; micro_header **preserves text** so localization auto-translate still matches), and animation helpers (`pop_in(control)` fade+slide open, `hover_lift(button)` brighten+scale+glow). ## Top conventions & gotchas
1. **Single-player needs `OfflineMultiplayerPeer`** — without it, authority checks return false and the player/AI freeze.
2. **Camera body-yaw coupling**: each frame `rotation.y += camera_pivot.rotation.y; camera_pivot.rotation.y = 0` (CameraPivot is a child of the body, so its yaw is local — assigning directly would double-count).
3. **Weapons fire via a converged two-stage raycast**: ray from the *camera* finds the crosshair point, then the shot fires from the *chest* toward it (bullets follow the crosshair; the spring-arm camera never shoots the player's own legs).
4. **Weapon view-model is reparented** from under the camera to `Player/WeaponMount` (hand height) so it's held in third-person, not stuck at the lens.
5. **AssetRegistry primitive fallback** + per-asset `model_scale`/`model_rot_deg`/`model_offset` — never hardcode models in scenes; collision/hitboxes are tied to capsule sizes, not art.
6. **`Settings.NET_DEBUG`** gates the `[net]/[arena]` diagnostic prints (off by default).
7. **One scene = one owner.** `.tscn` files merge poorly. `project.godot` and `Arena.tscn` are single-owner.
8. **Before parallel work**, add new input actions / `Events` signals / `Settings` constants / `AssetRegistry` ids FIRST, so agents code against stable interfaces. See `docs/AGENT_TEAMS.md`.
9. **`weapon_controller._load_weapons()` is the one place weapon stats are computed**: it duplicates each `WeaponData` then layers, in order, difficulty + `player_mods` mults → permanent weapon **perks** → equipped **attachments** (read locally from `MetaProgression`, so co-op is correctly per-peer). Mods are multiplicative on the dup, never on the source `.tres`. Add new gun modifiers here.
10. **Warnings-are-errors parse trap**: `var x := <Variant>` (e.g. `dict.get(...)`, an untyped ternary) fails to parse with "inferred from Variant". Use an explicit type (`var x: int = ...`). `--headless --import` does **not** catch lazy parse errors inside tab scripts — runtime-smoke by opening the Hub (`ui open_workshop` + each `hub_*`) to surface them.
11. **In-raid `Inventory` is server-authoritative + NOT auto-replicated** (its `stacks` hold `ItemData` refs). After any server-side change it **mirrors** a serialized `[{id,count}]` to the OWNING client (`_push_to_owner`→`_apply_remote`) so the client actually SEES its loot; never mutate a client's stacks locally (the next mirror overwrites it) — go through the server (`transfer_item`/`request_split`/the pickup RPC). The host's own inventory stays local.
12. **Save files are version-stamped + update-resilient**: `MetaProgression`/`Stash`/`SettingsManager` write `save_version` (`Settings.GAME_VERSION`) and on load defensively parse every field, **never wipe**, and `push_warning`+`Events.notify` once if the save is from a newer build. Bump `Settings.GAME_VERSION` with the `VERSION` file.
