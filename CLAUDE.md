# Hype Raiders — Project Guide (read me first)

**Hype Raiders** is an Arc Raiders-style **co-op third-person extraction shooter** vertical slice built in **Godot 4.6.3 stable**. Scavenge a hostile 160×160 urban-ruins map full of AI robots, survive escalating waves (incl. a boss), and reach an extraction zone alive — solo or in up-to-8 co-op. It runs **with zero art assets** (every model falls back to a tinted primitive via `AssetRegistry`).

This file is the always-loaded index. Depth lives in `docs/`:
- **`docs/ARCHITECTURE.md`** — autoloads, Events bus, Settings, physics layers, scene trees, every gameplay system.
- **`docs/TESTING.md`** — the self-play test harness (how Claude plays/screenshots the game) + QA workflow.
- **`docs/AGENT_TEAMS.md`** — the expected `agent_teams` team structure & ownership model for parallel work.

## Release / packaging (portable Windows build)
`pwsh tools/build/export_windows.ps1` → installs the 4.6.3 export templates on first run (one-time ~700 MB), regenerates `scripts/resource_index.gd`, exports a single self-contained exe (pck embedded) and zips it with a README, both into a **per-version folder** `export/v<VERSION>/` (`HypeRaiders.exe` + `HypeRaiders-v<VERSION>-win64.zip`) so older releases are never overwritten — each build wipes/refills only its own version's folder (friends unzip + run; co-op via the menu's Host/Join over UDP 24565). Bump the `VERSION` file per release. `export_presets.cfg` uses **`export_filter="all_resources"`** so the string-loaded `assets/*` + the data `.tres` ship. **Export gotcha (already handled):** `DirAccess` can't enumerate a `res://` dir inside a PCK, so `ItemCatalog`/`Crafting`/`Quests` scan empty in a build — they fall back to **`ResourceIndex`** (generated path lists; loading by explicit path works because Godot remaps it). Drop a new `.tres` → the next build regenerates the index. `export/` is gitignored.

## Self-play harness in 6 lines (how to actually test gameplay)
1. Launch `--agent` in the background → boots single-player, parks the window off-screen/no-focus, opens a TCP control server on `127.0.0.1:24700`. Add `--agent-port N` to run **multiple instances at once** (per-port control + screenshots + saves — `docs/TESTING.md` §7; `tools/agent/launch_agents.ps1`). **Git-worktree parallelism:** each worktree is isolated (own `.godot`/`export/`/`graphify-out/`); to also RUN instances from several worktrees concurrently use `--agent-port N` (control+saves+screenshots, disjoint range per worktree), `--net-port P` (ENet game port + discovery `P+1`; shared by a co-op group, distinct per worktree so two groups host at once — it is NOT derived from agent_port), and `--label <branch>` (folded into the window title `Hype Raiders_<branch> [a:N n:P]` so processes are tellable apart). `launch_agents.ps1 -BasePort -NetPort -Menu` wires all three + auto-labels from the git branch + pins this worktree's MCP target via `tools/agent/.agent_port` (gitignored; `mcp_server.py` resolves env `AGENT_PORT` → that file → 24700). Convention table + recipe: `tools/agent/README.md` "Parallel git worktrees".
2. Drive it with `python tools/agent/play.py <cmd>` — e.g. `state`, `move 0 1 0.5`, `aim`, `fire 0.3`, `goto <x> <z>`, `act reload`, `spawn boss`, `godmode on`, `tp <x> <z>`.
3. `python tools/agent/play.py screenshot foo` saves a PNG to `%APPDATA%\Godot\app_userdata\Hype Raiders\agent\foo.png` — then **Read** that PNG to see the game.
4. `play.py state` returns full JSON (player pos/health/weapon/ammo/ads, enemies w/ archetype+state, loot, extraction, wave, result).
5. Debug hooks for QA: `spawn`/`tp`/`godmode`/`restart`/`refill`/`render` (`{cmd:render, id, name}` → saves a clean isolated 3/4 render of any id's model to `agent/<name>.png` — the way to QA procedural models/icons, since the third-person camera makes in-world close-ups useless); `ui open_workshop|hub_stash|hub_loadout|hub_workshop|hub_shop|hub_quests|hub_gunsmith` (Lobby tabs); `stash {add|remove|bring|deploy|clear|craft|recycle|learn|buy|claim|give|currency|questprog | equip(weapon,slot,id)|unequip(weapon,slot)|perk(weapon,perk)|daily, id, count[, price]}`; `ui open_map|close_map` (the M-key Tactical Map); `clock {action:set,left:<s> | action:skip}` (drives the match timer — `skip` jumps to ~2s left to trigger the final storm wave); co-op from `--agent --menu`: `net {host|join, ip}` + `ready {on}` (client lobby ready-up) + `deploy` (leader START) + `transfer {from,to,id,count}` (server-auth give between peers) + `favorites {action:add|remove|connect|list, name,ip,port}` + `discover {timeout}` (LAN scan; results in `state.lan` after ~timeout) + `ui open_servers|close_servers` (the main-menu server browser). Drive N instances with `--agent-port N` and `python tools/agent/raw.py '<json>' <port>` (4-player tested). `state.meta` exposes currency/difficulty/loadout/bring/blueprints/quests + `attachments`/`weapon_perks`/`dailies`; `state.stash` the persistent items; top-level `stash_weight`/`stash_cap`; `state.match_timer{left,total,final_wave}` + `state.extraction_zones[]{name,pos,open,window_left}`; `state.peer_id` + `state.scoreboard{kills,deaths,mobs_killed}` (the synced TAB leaderboard data) + `state.favorites`/`recents`/`lan` (server browser). play.py only knows the base verbs — drive the `ui`/`stash`/`net` JSON commands with **`python tools/agent/raw.py '{"cmd":...}'`**. Saves at `%APPDATA%\Godot\app_userdata\Hype Raiders\{profile,stash}[_<port>].cfg`.

## Architecture at a glance
Systems are **decoupled through autoloads** — they emit/listen on the `Events` bus and read shared data, never referencing each other directly:
- **`Events`** — global signal bus (combat, weapons, loot, extraction, waves, net).
- **`Settings`** — all tunables (player/camera/ADS, enemy `ENEMY_STATS` table, waves, gadgets, `difficulty_mods()`).
- **`AssetRegistry`** — logical id → visual. Resolution order: real `.glb` → **`ProceduralModels.build(id)`** (rich multi-part meshes assembled in code: distinct enemy silhouettes + real item shapes, `scripts/visual/procedural_models.gd`) → CATALOG `parts` → tinted single primitive (game always runnable). `.glb` WINS over a builder — clear an id's `"model"` to use its procedural model. `get_icon` returns an authored PNG (weapons) else falls back to **`IconRenderer`**.
- **`IconRenderer`** — renders any id's 3D model to a transparent texture (off-screen SubViewport) for inventory icons; cache filled by a startup pre-warm so the UI `get_icon` is a sync cache hit (headless → null → UI colored box). Also the model-QA tool: AgentBridge `render` command saves a clean hero shot PNG (see harness). Procedural-model + SubViewport gotchas live in the `procedural-visual-harness` memory.
- **`GameState`** — match phase, wave, peer roster, win/lose resolution, `difficulty` (Easy/Normal/Hard).
- **`MetaProgression`** — persistent between-run profile (`user://profile.cfg`): currency, weapon unlocks, permanent upgrades (incl. **Stash Expansion** → `stash_capacity()`), deploy loadout (weapons) + `bring` (consumable bring-list), **`equipped_attachments`** (`weapon→{slot→att_id}`, at-risk) + **`weapon_perks`** (`weapon→{perk→level}`, permanent, `WEAPON_PERKS`) + daily-contract state (`last_daily_date`/`daily_quest_ids`). `player_mods()` read by player.gd + weapon_controller at match start; `reconcile_attachments()` unequips any attachment no longer in the stash (called on Hub open, after a loss eats it).
- **`ItemCatalog`** — scans `resources/items/*.tres` → `id → ItemData` (shared by loot / stash / loadout / craft).
- **`Stash`** — the **persistent item stash** (`user://stash.cfg`, per-instance via `Settings.user_path`): what you extract is kept here as real items; the at-risk economy (materials/consumables/valuables/**attachments** — weapons stay permanent unlocks). Has a **hard weight cap** (`total_weight()`/`capacity()` = `MetaProgression.stash_capacity()`); a deposit over cap fires `Events.haul_overflow` → the **Manage-Your-Haul** screen (`scenes/ui/HaulManager.tscn`, instanced by `main.gd`: sell/recycle/drop until under cap). Surfaced by the **Lobby/Hub** (`scenes/ui/Hub.tscn`: STASH / LOADOUT / WORKSHOP / SHOP / QUESTS / **GUNSMITH** tabs — GUNSMITH equips at-risk attachments + buys permanent perks).
- **World & match loop** — `scenes/world/Arena.tscn`+`arena.gd` swap the old cube POIs for **procedural modular buildings** (`scripts/visual/procedural_buildings.gd`, themed per POI, spawned at the POI markers *before* the runtime navmesh bake; courtyards left clear around the 3 extraction zones) over a textured ground + atmospheric sky (`resources/default_env.tres`). **Match timer**: `wave_manager.gd` counts `GameState.match_time_left` down from `Settings.MATCH_DURATION`; at 0 it sets `GameState.final_wave` and floods a **final "storm" wave** (interrupts the current wave, raises the alive-cap to `FINAL_WAVE_CONCURRENT`) forcing extraction. The 5 gradual waves are unchanged before it. **`ExtractionDirector`** autoload rotates per-zone **timed windows** (`extraction_zone.is_open()/window_remaining()/set_window()`; only an OPEN zone makes progress; all forced open during the storm). The **'M' Tactical Map** (`scenes/ui/MapUI.tscn`) shows POIs (zones of interest), every evac zone w/ open/closed + countdown, the player, enemies, and the match clock; the minimap mirrors window state; HUD shows the timer + storm banner. **Combat**: shots now have **bullet drop** (`weapon.gd` stepped ballistic raycast under `Settings.BULLET_GRAVITY`/`BULLET_MUZZLE_VELOCITY`, tracer follows the arc), punchier impact FX + enemy stagger, and a crosshair **hit-marker** (`scripts/ui/hit_marker.gd`). The **player model rotates smoothly** with the camera (body yaw is applied at render rate in `player.gd`, not deferred to the 60Hz physics tick).
- **`RaidManager`** — the per-player raid economy: `deploy()` commits the bring-list **and the loadout weapons' equipped attachments** (pulls them from the local stash, now at risk — `_committed_attachments`); `grant_extraction()` deposits a peer's haul + surviving attachments into ITS OWN stash on extract (host-local or via RPC to a client) + learns blueprints from extracted schematics, then fires `haul_overflow` if over the weight cap. **Death deposits nothing → gear + attachments lost. Extract → kept (attachments stay equipped).** Each co-op player keeps its own stash on its own machine.
- **`Crafting`** — data-driven recipes (scans `resources/recipes/*.tres` = `CraftRecipe`): `craft(r)` (inputs+currency → output), blueprint gating (`recipe_unlocked`), `recycle(id)` (item → materials), `buy_blueprint()`. Blueprints (`MetaProgression.unlocked_blueprints`) are learned 3 ways: extract a schematic (`learn_item`), buy in the SHOP, or a quest reward.
- **`Quests`** — data-driven contracts (scans `resources/quests/*.tres` = `QuestData`): advances `MetaProgression.quest_progress` from the Events bus (kill / extract / extract_item / reach_wave / pickup), `claim()` grants the reward once. **Daily contracts** (`QuestData.daily`): `get_daily_quests()` rotates a subset (`DAILY_COUNT`) once per real day keyed by `Time.get_date_dict_from_system()` (resets their progress, fires `dailies_rotated`); `standing()` = the non-daily contracts. The QUESTS tab shows a DAILY section above STANDING. A post-raid **`RaidSummary`** screen shows the haul + blueprints/quests and routes **Continue → back to the Hub** (→ Manage-Your-Haul if over cap).
- **`NetworkManager`** — listen-server host/join + **co-op squad lobby** + match-end broadcast. The **Hub IS the lobby** (auto-squad, host=leader=peer 1): clients toggle **READY** (`set_ready` RPC); the leader's **START RAID** (`request_start`, gated on all members ready) broadcasts `_begin_deploy` so EVERY peer deploys on the same tick; each peer's `load_arena` calls `notify_loaded` and `begin_match` fires only once **all** peers have loaded → `arena._on_match_started` spawns all players (never on peer-connect — that was the grey-screen bug). Client-owned spawn position is sent via `player._net_place`. Wave/match-timer state is mirrored to clients (`sync_wave`/`sync_match_timer`) so co-op HUDs match. The `Events.squad_changed` signal drives the Hub roster. **Co-op depth (server-authoritative):** `MAX_PLAYERS=8` (5–8 spawn on a golden-angle ring offset since there are only 4 markers); a CLIENT's weapon resolves its hit locally but routes damage via `request_hit` so the **server** applies it (its local `apply_hit` would only hit its own copy → enemy never dies); shots are rebroadcast (`broadcast_shot`→`Events.remote_shot`→`RemoteShotFX`) so teammates see each other's tracer/muzzle/impact; mob kills are attributed to the killer's peer on `Events.entity_died` and synced (`GameState.kills`/`deaths`/`mobs_killed` → `Events.scoreboard_changed`, shown on the **TAB** `Scoreboard`); `transfer_item`/`request_split`/`nearest_teammate` power GIVE (inventory ctx-menu) + the two-sided **TradeUI** (`trade`/T key); a disconnected peer's body is despawned + win/lose re-checked.
- **`ServerBrowser`** — local **server list + LAN discovery** for the main-menu browser (`scenes/ui/ServerBrowser.tscn`, opened by the menu's SERVERS button). Persists **favorites** + MRU **recents** to `favorites.cfg` (version-stamped, same resilient pattern as the other saves). `parse_addr("ip[:port]")`, `add_favorite/remove_favorite/record_connect`. **LAN:** a host auto-answers `HYPE_DISCOVER?` UDP pings on `Settings.DISCOVERY_PORT` (24566, separate from the ENet game port 24565); `scan_lan()` broadcasts (+ loopback for same-machine tests) and emits `Events.lan_servers_found`. The menu's `_join(ip,port)` is the single connect path (JOIN button + browser), now with connection-FAILURE feedback. The **Hub squad roster** is a bottom strip of `● nick` chips (amber=leader / green=ready / yellow=not-ready), synced from `GameState.peers`, shown whether you host or join.
- **`AudioManager`** — SFX off the Events bus. **`AgentBridge`** — the self-play control server.
- **Graphics quality / diagnostics / loading** (settings menu batch). **Godot does NOT auto-scale to hardware** — quality is hand-built. `SettingsManager` (`user://settings.cfg`) holds a `graphics_quality` preset (0 Low … 3 Ultra; Ultra = the authored look) plus per-lever overrides; `apply_quality_preset(level)` writes the whole bundle from `QUALITY_PRESETS` and `current_preset_or_custom()` reports "Custom" when a lever diverges. **Levers** — immediate: viewport `scaling_3d_scale` (render scale, the cheapest big win), `env.sdfgi_enabled`/`ssao_enabled`/`glow_enabled` + Sky3D `cumulus_visible`/`cumulus_noise_freq` (applied by `world_atmosphere.gd` on `Events.graphics_quality_changed`), MSAA, shadow-atlas size; **rebuild-bound** (read at the next arena build via `Settings.grass_density_scale` / `Settings.water_refraction`): grass cap in `procedural_flora._build_grass`, water `refract_amt` in `procedural_terrain._build_water`. **"Ultra+RT" tier (raster "RT-style" — Godot 4.6.3 has NO hardware ray tracing / path tracing; that's 4.7-Dev + an NVIDIA fork):** a 5th preset (`graphics_quality=4`) + manual toggles that turn on the best raster reflection/GI stack — **SSR** (`env.ssr_enabled`, Forward+-only, the headline; water/metal/wet), **SSIL** (`env.ssil_enabled`), **max SDFGI** (6 cascades + occlusion + higher bounce), and **Reflection Probes** (`scripts/visual/procedural_reflection_probes.gd`: `ReflectionProbe`s at POIs, `UPDATE_ONCE`, render-only, rebuild-bound via `Settings.reflection_probes_enabled`). **VoxelGI** is an experimental-only manual toggle (`Settings.voxelgi_enabled`, runtime bake, heavy — never in a preset; SDFGI is the right GI for the 160 m open map). All RT levers applied by `world_atmosphere._apply_graphics_quality` (env/SDFGI/SSR/SSIL immediate) + the probe placer at arena build.

**Cinematic pass III (toward filmic quality + crankable detail):** the philosophy is *presets stay safe, sliders push past Ultra* — every cinematic **slider has a numeric readout beside it + a sane clamp** (the player can dial back). New levers in `SettingsManager`/`world_atmosphere`/`procedural_*`: **global volumetric fog** (`env.volumetric_fog_enabled`+`volumetric_fog_density`, baseline props in `default_env.tres` but `enabled=false` so plain Ultra is unchanged), **localized `FogVolume` zones** (`scripts/visual/procedural_fog_zones.gd`: ELLIPSOID FogVolumes at the south-basin POIs + river-valley points, `FogMaterial.edge_fade`=0.5 SOFT transition + `height_falloff` ground mist, render-only/rebuild-bound via `Settings.local_fog_enabled`; render only when global volumetric fog is on), **god rays** (`DirectionalLight3D.light_volumetric_fog_energy`), **far-only depth of field** (`CameraAttributesPractical.dof_blur_far_*` on the WorldEnvironment node — never near-blurs the gun), **denser terrain mesh** (`Settings.terrain_detail_scale` → ground-grid cell `1.0/detail`, ≥0.5 m) + **parallax-occlusion mapping** in the triplanar `_GROUND_SHADER` (gated by `parallax_scale`, height from the existing roughness — no new assets; identical when off), **draw distance** (`Settings.draw_distance_scale` × flora/grass/tree `visibility_range_end`), **particle density** (`GPUParticles3D.amount_ratio`), **shadow distance** (`directional_shadow_max_distance`). Sliders: draw distance (m), grass density (to 200%), particles, terrain detail (×), volumetric-fog density, shadow distance (m), DOF; toggles: volumetric fog, local fog zones, god rays, DOF, terrain parallax. Real GPU tessellation isn't in 4.6.3 — POM + denser mesh is the equivalent. The **settings menu** (`scripts/ui/settings_menu.gd`) has GRAPHICS / AUDIO / CONTROLS / **INTERFACE** tabs — Graphics holds the 5-tier preset + manual toggles/sliders.

**Any-aspect display + Interface tab (ultrawide 32:9, 16:10/MacBook, 21:9, 4:3):** `project.godot` sets `window/stretch/mode="canvas_items"` + **`aspect="expand"`** so the game FILLS any monitor aspect (no letterbox/pillarbox; wider shows more horizontally — Camera3D `KEEP_HEIGHT`). The resolution dropdown is built at runtime by `SettingsManager.build_resolution_list()` (native via `DisplayServer.screen_get_size` + curated 16:9/16:10/21:9/32:9 modes ≤ native + the saved value), not a fixed 16:9 list. The new **INTERFACE settings tab** holds the stats-overlay options + ultrawide HUD-layout sliders: **UI horizontal/vertical offset** (`ui_edge_margin`/`ui_top_margin` → edge-anchored HUD insets toward center on `Events.ui_layout_changed`; minimap/killfeed/HUD-health/ammo/hints/stats re-inset from cached BASE offsets via `scripts/ui/ui_layout.gd`; center/fullscreen UI untouched) and **HUD scale** (`Window.content_scale_factor`). The **stats overlay** display mode now has a 3rd option **Graphs + Numbers** (`stats_display_mode=2` → rolling graph + numeric panel stacked). **Stats overlay** (`scenes/ui/StatsOverlay.tscn`, a persistent CanvasLayer child of `main.gd`, `mouse_filter=IGNORE`): `show_fps` (minimal FPS) + `show_detailed_stats` (perf via `Performance.get_monitor` + **per-peer network** RTT/loss via `ENetMultiplayerPeer.get_peer().get_statistic()`, hard-guarded to networked-only) in a `stats_display_mode` of Numeric or live rolling **Graphs** (custom `_draw()` + `queue_redraw()`, minimap pattern); driven by `Events.stats_overlay_changed`. **Loading screen** (`scenes/ui/LoadingScreen.tscn`, persistent CanvasLayer): `arena._ready` is now a coroutine that emits `Events.arena_build_progress(frac,label)` + `await`s a frame between terrain→structures→ground→flora→navmesh phases so a progress bar replaces the old freeze; `main.load_arena` shows it and **gates the load→match handshake (`notify_loaded`/`match_started`) on the build reaching 1.0** so players/enemies never spawn into a half-built world; a best-effort boot shader-prewarm runs behind it before the menu (`_boot_prewarm_then_menu`).

**QoL / combat-feel pass:** the player has stances — **crouch** (hold Ctrl/C: slower, lower camera) and **slide** (Ctrl while sprint-moving: momentum slide, lower camera, locked dir, `SLIDE_TIME`) — a `Stance` enum (STAND/CROUCH/SLIDE) in `player.gd` exposing `stance` + `stance_spread_mult()`. **Weapon spread is stance-based** (applied on the authoritative shot in `weapon.gd`): `spread_deg × stance_mult × (ADS?SPREAD_MULT_ADS:1)` — crouch<stand<move<sprint<slide, ADS tightest (`Settings.SPREAD_MULT_*`); the **dynamic crosshair** (`crosshair.gd`) reads `weapon_controller.current_spread_deg()` so the reticle gap = the real cone. **View modes:** `toggle_view` (V) flips 1st/3rd person (first-person hides the local `ModelRoot` + `FP_SPRING_LENGTH`); the SpringArm has collision (`mask` includes world layer 1 + `margin` 0.2) so the camera pulls in against walls/ceilings (anti-wallhack); Interface-tab sliders set `camera_distance`/`camera_shoulder` + a `default_view`, applied via `Events.camera_settings_changed`. Gun view-models were shrunk (`AssetRegistry` `model_scale`, rifle 0.55→0.34 etc.) so the held gun is visible but unobtrusive. **Hub UI** uses icon grids (SHOP/WORKSHOP/GUNSMITH/LOADOUT reuse the `inventory_ui::_make_slot` rarity-bordered icon cell via `AssetRegistry.get_icon`). UI overlap fixes: the Hub squad-roster strip clears the footer buttons, the in-raid killfeed stacks below the stats overlay, extraction/interaction/compass-timer are de-conflicted (`hub.gd`/`killfeed.gd`/`hud.gd`). (Also fixed a pre-existing `hub.gd` bug: the difficulty selector `@onready` paths missed the `DiffVBox` wrapper.)

**Co-op revive loop ("down but not out"):** lethal damage now DOWNS a player instead of instant death — `player._on_died` enters a DOWNED state (clears `Health.is_dead`, a small downed pool + `Settings.BLEEDOUT_TIME` bleedout, crawl-only at `DOWNED_MOVE_SPEED`, can still **ping**), synced via the player's MultiplayerSynchronizer (`downed`/`_carried_by_peer`). Bleedout or finish-damage → true death (`_true_death` → old resolution). **Server-authoritative**: `GameState.downed`/`revives` + `any_player_up()` — the **match is lost only when NO ONE is up** (a downed player alone isn't a loss). A teammate within `INTERACT_RANGE` of a downed buddy gets "Revive [hold E]" (`Events.interaction_available`) → `NetworkManager.request_revive` (server validates → `player.server_revive(by)` heals to `REVIVE_HEALTH_FRAC` + credits the reviver). **Self-revive** (`loot_self_revive` consumable) + **knockdown shield** (`loot_knockdown_shield`, soaks `KNOCKDOWN_SHIELD_ABSORB` while downed) + **carry** a downed buddy (hold F, `CARRY_SPEED_MULT`, sidearm only, synced anchor). **Comms:** middle-mouse **ping** (contextual enemy/loot/extraction/go-here, world markers + edge arrows, loot "dibs") + a hold-**Z** radial **comms wheel** (Help/Thanks/Regroup/Need Ammo) — `NetworkManager.broadcast_ping` → `Events.ping_placed` (`scripts/ui/ping_system.gd`/`comms_wheel.gd`, instanced in `main.gd`); a downed player can still ping. HUD shows a downed vignette + bleedout ring + teammate-downed arrow; the TAB scoreboard has a synced **Revives** column + a medic badge (reputation). Signals: `Events.player_downed/player_revived/player_bleedout/ping_placed`.

Authority/offline model: single-player uses an **`OfflineMultiplayerPeer`** (NOT a null peer) so `is_multiplayer_authority()`/`is_server()` pass locally; the same authority-gated code runs in single-player and co-op. Player authority is derived from the node name (`str(peer_id)`) in `_enter_tree`.

Cinematic grass = `shaders/grass.gdshader` (GodotGrass-style SSS+gradient+wind, MIT) on the tiled MultiMesh in `procedural_flora.gd`; terrain ground = ambientCG PBR triplanar height/slope splat in `procedural_terrain.gd`. **Water:** a real DEEP river (~2.7 m channel, ~33° walkable banks) in `procedural_terrain.gd` — `water.gdshader` is `DEPTH_TEXTURE` depth-fade + `SCREEN_TEXTURE` refraction (riverbed visible/distorted, natural teal-green), the AI crossing is a procedural **stone arch bridge** (deep channel doesn't bake navmesh → enemies cross the bridge). `ProceduralTerrain.water_surface_at(x,z)` (NaN off-river) is the contract `player.gd` uses to detect DRY/WADING/SUBMERGED → `Events.water_state_changed` drives a LOCAL `UnderwaterOverlay` (`shaders/underwater.gdshader` tint+wobble+vignette) + bubbles + splash SFX + a Master-bus lowpass (all authority-gated, no netcode). **Grass density is GPU-budgeted** (`NEAR_GRASS_CAP≈26000` in `procedural_flora.gd`) so weaker GPUs hold ≥150 fps — don't crank it back to 60k.

## Top conventions & gotchas
1. **Single-player needs `OfflineMultiplayerPeer`** — without it, authority checks return false and the player/AI freeze.
2. **Camera body-yaw coupling**: each frame `rotation.y += camera_pivot.rotation.y; camera_pivot.rotation.y = 0` (CameraPivot is a child of the body, so its yaw is local — assigning directly would double-count).
3. **Weapons fire via a converged two-stage raycast**: ray from the *camera* finds the crosshair point, then the shot fires from the *chest* toward it (bullets follow the crosshair; the spring-arm camera never shoots the player's own legs).
4. **Weapon view-model is reparented** from under the camera to `Player/WeaponMount` (hand height) so it's held in third-person, not stuck at the lens.
5. **AssetRegistry primitive fallback** + per-asset `model_scale`/`model_rot_deg`/`model_offset` — never hardcode models in scenes; collision/hitboxes are tied to capsule sizes, not art.
6. **`Settings.NET_DEBUG`** gates the `[net]/[arena]` diagnostic prints (off by default).
7. **One scene = one owner.** `.tscn` files merge poorly. `project.godot` and `Arena.tscn` are single-owner.
8. **Before parallel work**, add new input actions / `Events` signals / `Settings` constants / `AssetRegistry` ids FIRST, so agents code against stable interfaces. See `docs/AGENT_TEAMS.md`.
9. **`weapon_controller._load_weapons()` is the one place weapon stats are computed**: it duplicates each `WeaponData` then layers, in order, difficulty + `player_mods` mults → permanent weapon **perks** → equipped **attachments** (read locally from `MetaProgression`, so co-op is correctly per-peer). Mods are multiplicative on the dup, never on the source `.tres`. Add new gun modifiers here.
10. **Warnings-are-errors parse trap**: `var x := <Variant>` (e.g. `dict.get(...)`, an untyped ternary) fails to parse with "inferred from Variant". Use an explicit type (`var x: int = ...`). `--headless --import` does **not** catch lazy parse errors inside tab scripts — runtime-smoke by opening the Hub (`ui open_workshop` + each `hub_*`) to surface them.
11. **In-raid `Inventory` is server-authoritative + NOT auto-replicated** (its `stacks` hold `ItemData` refs). After any server-side change it **mirrors** a serialized `[{id,count}]` to the OWNING client (`_push_to_owner`→`_apply_remote`) so the client actually SEES its loot; never mutate a client's stacks locally (the next mirror overwrites it) — go through the server (`transfer_item`/`request_split`/the pickup RPC). The host's own inventory stays local.
12. **Save files are version-stamped + update-resilient**: `MetaProgression`/`Stash`/`SettingsManager` write `save_version` (`Settings.GAME_VERSION`) and on load defensively parse every field, **never wipe**, and `push_warning`+`Events.notify` once if the save is from a newer build. Bump `Settings.GAME_VERSION` with the `VERSION` file.

## Parallel work with agent teams
Big features were built by a team named **`arc-raiders`**: the **lead owns the shared "spine"** (project.godot, autoloads, player.gd, Player.tscn, HUD, integration, the harness) and integrates; each agent owns **one isolated lane** (new files + at most one existing script) so no two agents touch the same file. Pattern: **frozen foundation → parallel isolated workstreams → integrate at single wiring points → play-test via the harness → optional read-only review pass.** Full role list, file lanes, and spawn recipe: **`docs/AGENT_TEAMS.md`**.

- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
