# Hype Raiders — Project Guide (read me first)

**Hype Raiders** is an Arc Raiders-style **co-op third-person extraction shooter** vertical slice built in **Godot 4.6.3 stable**. Scavenge a hostile **320×320** urban-ruins map full of AI robots, survive escalating waves (incl. a boss), and reach an extraction zone alive — solo or in up-to-8 co-op. It runs **with zero art assets** (every model falls back to a tinted primitive via `AssetRegistry`).

**Map: 4× expansion (v0.3).** The world is a **320×320 rectangle** X∈[−80,240], Z∈[−80,240] (centre 80,80). The original 160×160 map is the **NW quadrant** (all original content kept its exact coords; bounds in **`scripts/core/world_bounds.gd`** (`WorldBounds` — the ONE source for the rect + `biome_at`)). The 3 new quadrants each have a **themed landmark + filler POI + a localized climate zone**: **NE→snow** (alpine Lodge + depot), **SW→desert** (sandstone Ruins ×2), **SE→rain** (Japanese Temple + shrine house). New building themes `temple`/`snow_lodge`/`desert_ruins` in `procedural_buildings.gd`; `_POI_DEFS` has 12 POIs (POIMarkers order MUST match the keys — tiers/loot/power-caches map by index). **`ProceduralClimateZones`** (`scripts/visual/procedural_climate_zones.gd`, clones the FogZones discipline) places POINTWISE rain/snow/desert at the 3 landmarks (GPUParticles + ground Decal + FogVolume; render-only, deterministic, `Settings.climate_zones_enabled`/`climate_density`, Graphics-tab toggle+slider). Flora/atmosphere scatter the full rectangle (grass is density-driven + tiled so per-frame cost is unchanged); the river stays in the NW quadrant (shallowed south terminus, banks still split). Enemy spawning got a deterministic golden-angle de-stack jitter (`wave_manager._jittered_spawn`) so a burst on one marker no longer piles vertically. **Biome fauna (9 mechanical enemies, BIOME-EXCLUSIVE):** every spawn resolves its point FIRST, classifies it via **`WorldBounds.biome_at(x,z)`**, and draws from that biome's pool (`wave_manager` `BIOME_WAVE_POOLS`/`BIOME_STORM_POOLS`/`BIOME_PATROL_POOLS`; urban = the classic roster; wave-5 boss global; markers NEAR a player are preferred — `NEAR_SPAWN_RADIUS`). **Desert:** `robot_sandworm` (`robot_worm.gd` — the flagship BURROWER: replicated `phase` int 0 BURROWED→1 EMERGE-leap→2 SURFACE-crawl/bite (the kill window, maw ×2.5)→3 SUBMERGE; underground = hidden+untargetable, fast straight-line travel pinned under `ProceduralTerrain.height_at`, dust-trail GPUParticles; clients drive visuals purely off `phase`; also a desert PATROL ambusher), `robot_scarab` (`robot_kamikaze.gd` — arms in range, blinking-core fuse, AoE self-destruct), `robot_dustdevil` (`robot_strafer.gd` — grounded wasp-style orbit-strafing gunner). **Snow:** `robot_frosthound` + `robot_kappa` share **`robot_pouncer.gd`** (stats-driven lunge/high-pounce arcs; gravity=20 — apex=up²/40), `robot_cryomortar` (`robot_mortar.gd` — burst artillery whose hits SLOW the player via the new `player.server_apply_slow` rpc_id plumbing), `robot_avalanche` (`robot_slammer.gd` — telegraphed ~1s windup → AoE ground slam; committed once winding). **Rain:** `robot_oni` (stats-only brute, WeakPoint on its BACK ×3), `robot_kappa`, `robot_raiju` (`robot_blinker.gd` — hitscan + sideways navmesh-snapped BLINK teleports). Big-body melee needs `attack_range` > its parking distance (body radii + separation: avalanche 3.8, oni 3.4). All 11 enemy scenes must be in `Net/EnemySpawner._spawnable_scenes` (Caller/Elite were MISSING → never replicated to co-op clients — fixed). Harness spawn ids: `worm/scarab/dustdevil/frosthound/cryomortar/avalanche/oni/kappa/raiju`; worm exposes `phase` in `state.enemies[]`. RaidSummary's solo pause is now leak-proof (teardown-refire gate on `GameState.phase` + a self-healing visible-only watchdog). The 4 perimeter wall colliders in `Arena.tscn` (`Walls/Wall*`, layer 1) were resized 162→322 + repositioned to ring the NEW rectangle (were stuck at the old ±80, forming an invisible mid-map cross). **Extraction: 12 zones** (`ExtractionZone`..`ExtractionZone12`) — the original 3 NW + 3 per new biome — all auto-register via the `"extraction"` group (no director change) + get terrain pads in `_collect_pads`. Loot/boosters fill the new quadrants: `arena._scatter_field_loot` drops open-area loot across the L-shaped new region (x>82 or z>82; server-only + replicated), and `_populate_power_caches` gives EVERY new POI (index ≥ 6) a power-cache + scatters 6 more; flora keep-outs (derived at build from arena `_POI_DEFS` + the NW `ExtractionZone*` positions — no hand-copied rect list) + new-quadrant rubble (`_rebuild_scatter`, placed at `height_at`) were added.

**Интерактив мира (v0.4):** window glass is **transparent + breakable** — every pane is a `BreakableGlass` StaticBody (`scripts/world/breakable_glass.gd`; intact glass now blocks bullets/enemy LOS) replicated BY INDEX (deterministic `_glass_seq` + static registry; wall roots are anonymous → node-path RPCs impossible) via `NetworkManager.request_break_glass` (client rpc_id(1) → server validates + noise 12.0 → authority call_local broadcast; restart restores all panes). **Vertical access**: `scripts/visual/procedural_stairs.gd` — a flight's COLLISION is one solid ≤36° ramp box (CharacterBody3D can't step stairs) + render-only treads; slab/roof holes open at clearance **2.6** (capsule 1.8 + 0.4 radius on the slope — the theoretical 2.1 jams, live-QA'd). Tower/warehouses/non-court houses reach their roofs via stacked flights; the court house gets ONE flight to the wing floor (same-lane switchbacks wedge shut on headroom — geometrically impossible; wing roof is decorative); container yards get a 35.6° ramp ending on a flat **landing deck** level with the 5.2 stack (a deck front edge proud of the slope line reads as a >45° lip-wall) + a 3-column mantle crate chain 1.15/2.30/3.30 (mantle-legal rises are (0.9,1.2] — the chest probe at feet+0.9 misses lower ledges) with a 0.7 walk-off drop. **Loot never floats**: `LootPickup.spawn_at` snaps the spawn point to the surface below SERVER-side before replication. Regression net: `python tools/agent/loot_audit.py` (floater scan + 6 live climbs, GREEN; enemies path upstairs — the navmesh bakes the ramps). Harness traps it encodes: `goto` holds forward its FULL duration (never stops at the target) and blocks its TCP reply till done; `tp` preserves current Y; agent jump = the `hold` verb pulse (`act jump` is a no-op for mantles); a KIA player still reports `drivable:true` but `fire` won't discharge — `input_enabled:false` is the tell, godmode co-op casts right after deploy.

**SIGNATURE MECHANIC — Machine Nemesis (v0.4; MVP + Phases 2–4 shipped 2026-06-13):** the game's identity hook (chosen after a 6-angle web-research sweep: the genre's fatal flaw is forgettable/repetitive raids, and the one un-copyable lever is that THESE enemies are MACHINES). **MACHINE CHEMISTRY (v0.4; Phase 5 shipped 2026-06-13):** the machine-themed DEEPENING of the signature — machines react to electro/thermo/cryo effects no human enemy can («water conducts, heat overheats, cold freezes, a frozen machine shatters»). An ENEMY status-effect framework with 4 statuses + emergent reactions. **`EnemyStatus`** (`scripts/enemies/enemy_status.gd`, the enemy-side mirror of `PlayerStatus`) is **code-instantiated** in `robot_enemy._ready()` (`add_child` — NO scene edit; 21 enemy `.tscn` each carry their OWN ReplConfig, so per-enemy replicated props were rejected): AUTHORITY-LOCAL logic (the result replicates implicitly via `Health.current`/position, exactly like the EMP stun), delta-accumulated BURN DoT (`is_dot_tick()` guard so it skips the brittle filter). **`MachineChemistry`** (`scripts/core/machine_chemistry.gd`, a static sibling of `CombatAoe`/`Steering`) holds ALL cross-cutting logic: `apply(enemy,kind,dur,mag)` resolves CLIMATE via `WorldBounds.biome_at` (desert burn ×`CHEM_BURN_DESERT_MULT` 1.5, snow slow-dur ×`CHEM_SLOW_SNOW_MULT` 1.5, rain/wet douses burn ×`CHEM_BURN_RAIN_MULT` 0) + WETNESS (`is_wet` = biome rain OR over the river via the frozen `ProceduralTerrain.water_surface_at`), then fires REACTIONS — **freeze→shatter** (a deep SLOW `mag ≤ CHEM_FREEZE_THRESHOLD` auto-latches BRITTLE) and the headline **wet+shock chain discharge** (`discharge()` arcs SHOCK to the nearest unvisited WET machines within `CHEM_CHAIN_RADIUS` 6m, `CHEM_CHAIN_JUMPS` 3, per-hop falloff). The 4 statuses: **SHOCK** (reuses the enemy's `apply_stun` clock — one stun clock, inherits boss/`emp_hard` resist; the `apply_stun` deadline became `maxi`-harmonized so a short shock can't cut a long EMP), **BURN** (DoT via `Health.take_damage`), **SLOW** (scales `_apply_movement` speed; `_update_stuck` accrual paused while slowed so it never false-recovers), **BRITTLE** (incoming-damage ×`CHEM_BRITTLE_MULT` 1.5 via the enemy's `Health.damage_filter` — enemies otherwise leave it UNSET; a brittle kill fires `Events.notify "SHATTER!"`). **Co-op visual sync**: the status LOGIC is server-only, but `robot_enemy.sync_chemistry_flags` (`@rpc("authority","call_local","reliable")`, dispatched duck-typed via `_e.rpc("sync_chemistry_flags",flags)` from the child component) broadcasts the active-flag set on every EDGE → every peer builds/frees the per-status FX aura (`MachineChemistry.make_fx`, render-only, distance-gated `CHEM_FX_DIST`); zero new scene edits (late-joiner misses in-flight flags — acceptable, effects are 1–6s). **Sources = grenades + EMP-shock** (loot-only, auto-enter `LootTables` by rarity — zero table edits): new **Incendiary** (`grenade_incendiary.gd`→BURN) + **Cryo** (`grenade_cryo.gd`→SLOW→BRITTLE) grenades (mirror `grenade_emp.gd`; `Settings.GRENADE_TYPES`/`GRENADE_ITEM_IDS`/`NetThrowables.GRENADE_SCENES`/`resource_index`/`loot_pickup`/`player._on_item_use` registrations), and the existing **EMP grenade now ALSO tags SHOCK** in its stun loop (the only player-side shock → unlocks the rain chain). **Nemesis tie-in (telemetry only in v1)**: `Events.enemy_chemistry_applied(enemy,kind,active)` feeds `NemesisDirector._tracked_chemistry`; the `chemistry_resist` learned trait (letter "C") is DEFERRED to Phase 6 (data accrues now). ## Release / packaging (portable Windows + macOS builds)
**Timestamped** layout: `export/v<VERSION>/<yyyy-MM-dd_HH-mm-ss>/windows/` + `.../mac/` — every build goes to a NEW dated folder so previous builds are PRESERVED for rollback (older builds are never overwritten; just grab the exe/zip from an earlier timestamp folder). **Build BOTH platforms with one command: `pwsh tools/build/export_all.ps1`** — it generates ONE shared timestamp, runs both export scripts into the same dated folder, and does a post-build exe alive-check. (The individual `export_windows.ps1`/`export_macos.ps1` still work standalone — each takes an optional `-Stamp`; run alone, each generates its own stamp.) Bump the `VERSION` file per release. **Windows:** `pwsh tools/build/export_windows.ps1` → installs the 4.6.3 export templates on first run (one-time ~700 MB), regenerates `scripts/resource_index.gd`, exports a single self-contained exe (pck embedded) + zips it with a README (`windows/HypeRaiders.exe` + `HypeRaiders-v<VERSION>-win64.zip`; friends unzip + run; co-op via Host/Join over UDP 24565). **macOS (built FROM Windows):** `pwsh tools/build/export_macos.ps1` → `mac/HypeRaiders-v<VERSION>-mac.zip` containing a **universal (Apple-Silicon arm64 + Intel) `Hype Raiders.app`** with a built-in **ad-hoc signature** (mandatory on arm64; Godot signs cross-platform, no Xcode), validated structurally (the script asserts the `.app/Contents/MacOS` entry + the fat Mach-O `CAFEBABE` magic) + `README-mac.txt` with the Gatekeeper first-launch steps (right-click→Open / `xattr -cr`) — not notarized (no Apple cert), so the warning is expected; a `.dmg` can't be made from Windows. **Gotchas:** the `macOS` preset (`[preset.1]`) requires the PROJECT setting `rendering/textures/vram_compression/import_etc2_astc=true` (Apple GPUs need ETC2/ASTC — without it the export refuses for arm64/universal; enabling it triggers a one-time texture reimport), and the Godot-made mac zip must ship **AS-IS** — never unzip+re-zip a `.app` on Windows (strips unix exec bits → app won't launch; the README sits NEXT to the zip). `export_presets.cfg` uses **`export_filter="all_resources"`** so the string-loaded `assets/*` + the data `.tres` ship. **Export gotcha (already handled):** `DirAccess` can't enumerate a `res://` dir inside a PCK, so `ItemCatalog`/`Crafting`/`Quests` scan empty in a build — they fall back to **`ResourceIndex`** (generated path lists; loading by explicit path works because Godot remaps it). ## Architecture at a glance
Systems are **decoupled through autoloads** — they emit/listen on the `Events` bus and read shared data, never referencing each other directly:
- **`Events`** — global signal bus (combat, weapons, loot, extraction, waves, net).
- **`Settings`** — all tunables (player/camera/ADS, enemy `ENEMY_STATS` table, waves, gadgets, `difficulty_mods()`).
- **`AssetRegistry`** — logical id → visual. Resolution order: real `.glb` → **`ProceduralModels.build(id)`** (rich multi-part meshes assembled in code: distinct enemy silhouettes + real item shapes, `scripts/visual/procedural_models.gd`) → CATALOG `parts` → tinted single primitive (game always runnable). `.glb` WINS over a builder — clear an id's `"model"` to use its procedural model. `get_icon` returns an authored PNG (weapons) else falls back to **`IconRenderer`**.
- **`IconRenderer`** — renders any id's 3D model to a transparent texture (off-screen SubViewport) for inventory icons; cache filled by a startup pre-warm so the UI `get_icon` is a sync cache hit (headless → null → UI colored box). Also the model-QA tool: AgentBridge `render` command saves a clean hero shot PNG (see harness). Procedural-model + SubViewport gotchas live in the `procedural-visual-harness` memory.
- **`GameState`** — match phase, wave, peer roster, win/lose resolution, `difficulty` (Easy/Normal/Hard).
- **`MetaProgression`** — persistent between-run profile (`user://profile.cfg`): currency, weapon unlocks, permanent upgrades (incl. **Stash Expansion** → `stash_capacity()`), deploy loadout (weapons) + `bring` (consumable bring-list), **`equipped_attachments`** (`weapon→{slot→att_id}`, at-risk) + **`weapon_perks`** (`weapon→{perk→level}`, permanent, `WEAPON_PERKS`) + daily-contract state (`last_daily_date`/`daily_quest_ids`). `player_mods()` read by player.gd + weapon_controller at match start; `reconcile_attachments()` unequips any attachment no longer in the stash (called on Hub open, after a loss eats it).
- **`ItemCatalog`** — scans `resources/items/*.tres` → `id → ItemData` (shared by loot / stash / loadout / craft).
- **`Stash`** — the **persistent item stash** (`user://stash.cfg`, per-instance via `Settings.user_path`): what you extract is kept here as real items; the at-risk economy (materials/consumables/valuables/**attachments** — weapons stay permanent unlocks). Has a **hard weight cap** (`total_weight()`/`capacity()` = `MetaProgression.stash_capacity()`); a deposit over cap fires `Events.haul_overflow` → the **Manage-Your-Haul** screen (`scenes/ui/HaulManager.tscn`, instanced by `main.gd`: sell/recycle/drop until under cap). Surfaced by the **Lobby/Hub** (`scenes/ui/Hub.tscn`: STASH / LOADOUT / WORKSHOP / SHOP / QUESTS / **GUNSMITH** / RAIDER / **CHARACTER** tabs — GUNSMITH equips at-risk attachments + buys permanent perks).
- **Character customization (procedural modular player)** — the player is now a **procedural robot** built from swappable parts (`scripts/visual/procedural_player.gd`, same helpers as the enemy `ProceduralModels`), NOT the old `raider.glb`. `ProceduralPlayer.build_player(cosmetics)` assembles **head / torso / arms / legs** (≥10 distinct variants each) + a **paint** colour scheme (10) from a FROZEN catalog (`VARIANTS`/`PAINTS`); `AssetRegistry.get_model("player", cosmetics)` routes to it. The **CHARACTER Hub tab** (`scenes/ui/tabs/character_tab.gd`, tab index 7) is the constructor: category selector + a variant grid of `IconRenderer.render_cosmetic(...)` thumbnails (owned/EQUIPPED vs **BUY (CR n)**) + a **live rotating 3D `SubViewport` preview**. Economy in `MetaProgression`: `unlocked_cosmetics`/`equipped_cosmetics` (saved in `profile.cfg`), `is_cosmetic_unlocked`/`unlock_cosmetic`/`set_equipped_cosmetic`/`get_cosmetics()`; free starter variants (cost 0) always available; `Events.cosmetics_changed`. **MP appearance sync**: `player.gd` has a spawn-replicated `cosmetics: Dictionary` (Player.tscn `SceneReplicationConfig`, like `stance`/`downed`) — the authority sets it from its OWN `MetaProgression.get_cosmetics()` at spawn, it replicates to every peer, and a `_physics_process` watcher rebuilds the body (`_build_player_model` → `PlayerAnimator.reinit()`) so **every peer sees each player's chosen look** (verified host↔client). Harness: `raw.py '{"cmd":"cosmetic","action":"equip|buy|grant|get","id":...}'` + `ui hub_character`; `state.players[]` now exposes each player's replicated `cosmetics`.
- **World & match loop** — `scenes/world/Arena.tscn`+`arena.gd` swap the old cube POIs for **procedural modular buildings** (`scripts/visual/procedural_buildings.gd`, themed per POI, spawned at the POI markers *before* the runtime navmesh bake; courtyards left clear around the 3 extraction zones) over a textured ground + atmospheric sky (`resources/default_env.tres`). **Match timer**: `wave_manager.gd` counts `GameState.match_time_left` down from `Settings.MATCH_DURATION`; at 0 it sets `GameState.final_wave` and floods a **final "storm" wave** (interrupts the current wave, raises the alive-cap to `FINAL_WAVE_CONCURRENT`) forcing extraction. The 5 gradual waves are unchanged before it. **`ExtractionDirector`** autoload rotates per-zone **timed windows** (`extraction_zone.is_open()/window_remaining()/set_window()`; only an OPEN zone makes progress; all forced open during the storm). The **'M' Tactical Map** (`scenes/ui/MapUI.tscn`) shows POIs (zones of interest), every evac zone w/ open/closed + countdown, the player, enemies, and the match clock; the minimap mirrors window state; HUD shows the timer + storm banner. **Combat**: shots now have **bullet drop** (`weapon.gd` stepped ballistic raycast under `Settings.BULLET_GRAVITY`/`BULLET_MUZZLE_VELOCITY`, tracer follows the arc), punchier impact FX + enemy stagger, and a crosshair **hit-marker** (`scripts/ui/hit_marker.gd`). The **player model rotates smoothly** with the camera (body yaw is applied at render rate in `player.gd`, not deferred to the 60Hz physics tick).
- **Living threat (AI perception + sound stealth + reactive director)** — enemies are no longer a fixed timed trickle of force-aggro rushers. The FSM (`scripts/enemies/enemy_state_machine.gd`) gains an **`INVESTIGATE`** state (enum appended LAST so the replicated 0/1/2 PATROL/CHASE/ATTACK ints don't shift); `robot_enemy.gd` adds **server-side perception**: it HEARS players (each ~0.4 s retarget tick it reads `player.noise_radius()` — crouch quiet, walk medium, sprint loud, idle faint, downed near-silent; derived from the player's SYNCED position-speed + synced `stance`, NOT velocity) and reacts to loud `Events.noise_emitted` spikes (gunfire/grenade) → walks to the last-heard point (INVESTIGATE), promotes to CHASE on confirmed LOS, gives up after `INVESTIGATE_GIVEUP`. Entering CHASE **cascades** an alert to nearby non-hunter enemies (`alert_to`, refractory-gated). The **`hunter`** flag is still a force-CHASE override, so **wave/storm enemies rush exactly as before** — only NON-hunter **patrols** (spawned between waves) use the new senses and can be **stealthed past by crouch-walking**. Noise is **server-authoritative**: gunfire (`weapon.gd`) + grenades (`grenade.gd`) route through **`NetworkManager.report_noise(pos, radius, kind)`** (host emits directly; a client `rpc_id(1)`s so the SERVER's AI hears it). A **suppressor** (`att_suppressor.tres` `noise_mult=0.35` → `WeaponData.noise_mult`, layered in `weapon_controller._apply_attachments`) shrinks the gunfire aggro radius. New archetypes in `Settings.ENEMY_STATS`: a **caller/"Snitch"** (`robot_caller.gd`/`RobotCaller.tscn`, low HP, keeps distance, its `_strike` fires `Events.enemy_alerted` instead of damage) and an **elite** grunt (`RobotElite.tscn`, tankier + a ×2.5 `WeakPoint` Hurtbox Area). **Weak points** are `Hurtbox` Areas with `damage_multiplier` (head ≈2.0–2.5×, mirroring Bastion's `WeakPoint`) now on grunt/heavy/elite (pure scene; the body Hurtbox is untouched so normal shots still register). The **`AIDirector`** autoload (`autoload/ai_director.gd`, mirrors the `ExtractionDirector` pattern) listens to `enemy_alerted`/loud `noise_emitted` and, on a cooldown, summons reinforcements via the active `WaveManager` (which registers itself); `wave_manager.gd` adds **camp-punish** flank spawns (squad clustered within `DIRECTOR_CAMP_RADIUS` for `DIRECTOR_CAMP_TIME` → hunters spawn around the centroid), **boss-phase adds** (boss < `DIRECTOR_BOSS_ADD_HP` → elite adds once), and between-wave **patrols** (tracked in a separate `_patrols` array, freed at wave start so they never break wave-clear accounting). All gated on `is_local_authority_server()`; reactive spawns cap at `FINAL_WAVE_CONCURRENT`. ## Localization (en base + ru; scalable)
**Scheme: "English-as-key" + Godot auto-translate.** All translations live in ONE file — **`locale/ui.csv`** (`keys,ru[,de,...]`; the key IS the exact English source string; UTF-8; multi-line strings = real newlines inside quotes). Godot imports it to `locale/ui.*.translation`, registered in `project.godot [internationalization]` (fallback=en — English needs NO column: tr() falls back to the key). The language is the **`"language"` setting** (`SettingsManager`, default "en") applied via `TranslationServer.set_locale` — picker in Settings → INTERFACE (its own OptionButton has auto_translate DISABLED so "English/Русский" stay native). **Adding a language = add a CSV column + one `add_item`/lang_codes entry in `settings_menu.gd`.** How it works: Godot Controls AUTO-translate their `text`/`tooltip_text`/`placeholder_text`/OptionButton items at draw time — including text set from code — and re-translate LIVE on locale change; so STATIC strings need only a CSV row, while **format templates/concatenations/`Events.notify` payloads must go through `tr()`** (`tr("WAVE %d") % n` — tr the TEMPLATE; data-names substituted into templates get tr() too). `.tres` display_name/description and the Settings/MetaProgression catalogs are NOT modified — their English values are the CSV keys. **RULES for new code:** any new user-facing string gets a `locale/ui.csv` row immediately; if you EDIT an English string in code/scene/tres you MUST update its CSV key (key drift = silently untranslated); never translate ids/player names/IPs; strings compared in logic stay untranslated.

## UI look ("military glass" — theme-first)
The UI is a **dark translucent "military glass"** skin (Battlefield 2042 / Arc Raiders): chamfered translucent panels, thin light borders, amber accent bars + glow, spaced-caps headings, subtle scanlines, frosted-glass blur behind modals. It is built **in code**, reached three ways:
- **Global theme `assets/ui/theme.tres`** (project.godot `gui/theme/custom`) — every default Control inherits it: **Oswald** body font, **Russo One** heading face (via theme type variations **`HeaderLarge`** 30px / **`HeaderSmall`** 14px dim), translucent chamfered glass Buttons/Panels/LineEdits, amber hover-glow, teal ProgressBar fill (+ an amber **`FillAmber`** ProgressBar variation). Both fonts ship **Cyrillic** for the RU locale (`assets/fonts/`, SIL OFL). Restyling most of the UI = editing this one file.
- **`scripts/ui/ui_style.gd` (`class_name UIStyle`)** — stateless helper, the single source of truth the in-code screens call: palette consts (`UIStyle.AMBER/TEAL/DIM/WHITE/RED/GREEN/GLASS_BG/BORDER_LT`), StyleBox factories (`glass_panel()`, `header_panel(accent)` = glass + accent top bar + glow, `chip(color)`, `glow_fill(color)`), label helpers (`micro_header(text)`, `make_header(label,…)` — both apply the Russo One face; micro_header **preserves text** so localization auto-translate still matches), and animation helpers (`pop_in(control)` fade+slide open, `hover_lift(button)` brighten+scale+glow). Sibling of `UILayout`. **Don't re-add per-file `COL_*` consts — use `UIStyle.*`.**
- **FX layer:** `scripts/ui/fx_overlay.gd` (persistent CanvasLayer instanced in `main.gd`) draws the **scanline/grain/vignette veil** over SHELL UI only (menu/hub/pause/summary — hidden in live raid via match-state signals); `scripts/ui/glass_backdrop.gd` (`class_name GlassBackdrop`, `new()` → `move_child(bg,0)`) is the **frosted-glass blur** placed behind a modal's panel. Both gated by the **`ui_fx_enabled`** setting (Interface tab → `Events.ui_fx_changed` → `Settings.ui_fx_enabled`); off → plain dim fallback (no shader cost). Shaders: `shaders/ui_scanline.gdshader`, `shaders/ui_blur.gdshader` (the blur reads `hint_screen_texture`). **New UI:** prefer the theme + `UIStyle` factories over hand-rolled StyleBoxes/colors; titles get `make_header`/`HeaderLarge`, sections `micro_header`/`HeaderSmall`, modals get a `GlassBackdrop` + `pop_in`.

## Top conventions & gotchas
1. **Single-player needs `OfflineMultiplayerPeer`** — without it, authority checks return false and the player/AI freeze.
2. **Camera body-yaw coupling**: each frame `rotation.y += camera_pivot.rotation.y; camera_pivot.rotation.y = 0` (CameraPivot is a child of the body, so its yaw is local — assigning directly would double-count).
3. **Weapons fire via a converged two-stage raycast**: ray from the *camera* finds the crosshair point, then the shot fires from the *chest* toward it (bullets follow the crosshair; the spring-arm camera never shoots the player's own legs).
4. **Weapon view-model is reparented** from under the camera to `Player/WeaponMount` (hand height) so it's held in third-person, not stuck at the lens.
5. **AssetRegistry primitive fallback** + per-asset `model_scale`/`model_rot_deg`/`model_offset` — never hardcode models in scenes; collision/hitboxes are tied to capsule sizes, not art.
6. **`Settings.NET_DEBUG`** gates the `[net]/[arena]` diagnostic prints (off by default).
7. **One scene = one owner.** `.tscn` files merge poorly. `project.godot` and `Arena.tscn` are single-owner.
8. **Before parallel work**, add new input actions / `Events` signals / `Settings` constants / `AssetRegistry` ids FIRST, so agents code against stable interfaces. See `docs/AGENT_TEAMS.md`.
9. **`weapon_controller._load_weapons()` is the one place weapon stats are computed**: it duplicates each `WeaponData` then layers, in order, difficulty + `player_mods` mults → permanent weapon **perks** → equipped **attachments** (read locally from `MetaProgression`, so co-op is correctly per-peer). Mods are multiplicative on the dup, never on the source `.tres`. Add new gun modifiers here.
10. **Warnings-are-errors parse trap**: `var x := <Variant>` (e.g. `dict.get(...)`, an untyped ternary) fails to parse with "inferred from Variant". Use an explicit type (`var x: int = ...`). `--headless --import` does **not** catch lazy parse errors inside tab scripts — runtime-smoke by opening the Hub (`ui open_workshop` + each `hub_*`) to surface them.
11. **In-raid `Inventory` is server-authoritative + NOT auto-replicated** (its `stacks` hold `ItemData` refs). After any server-side change it **mirrors** a serialized `[{id,count}]` to the OWNING client (`_push_to_owner`→`_apply_remote`) so the client actually SEES its loot; never mutate a client's stacks locally (the next mirror overwrites it) — go through the server (`transfer_item`/`request_split`/the pickup RPC). The host's own inventory stays local.
12. **Save files are version-stamped + update-resilient**: `MetaProgression`/`Stash`/`SettingsManager` write `save_version` (`Settings.GAME_VERSION`) and on load defensively parse every field, **never wipe**, and `push_warning`+`Events.notify` once if the save is from a newer build. Bump `Settings.GAME_VERSION` with the `VERSION` file.
